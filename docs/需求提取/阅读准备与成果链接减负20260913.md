# 阅读准备与成果链接减负

更新：2026-09-13。承接[结构编制收敛](结构编制机械收敛20260913.md)，本轮将已确认的读取准备、版本参数和成果导航机械工作交回工具。没有重新调用模型，未改旧模型成果或前端。

## 已实现

1. 请求 `source_read` 的页文/高清图时，缺少逐页阅读材料会自动执行已有 `reading-workspace` 并登记工件。并发请求由同一任务准备锁串行化，后续直接复用；返回实际 revision 和准备回执。原件捕获仍需 `source_prepare`，不在读取时重新解析原文。首次准备沿用已有全页生成方式，不宣称大型 PDF 首图延迟已优化。
2. 原件索引继续保留短整数 ref 用于 Map 编制，同时提供带 capture 版本的读取 handle 和完整请求。任务只有一个已登记 capture 身份时，短整数读取可自动补版本；多个版本仍需明确 handle/hash。显式旧版本、未知引用、图像与页码冲突均在准备前拒绝。
3. 原件图片的准确 capture occurrence/ref 可以供程序定位页码；Map/条目阶段的 image anchor 继续使用各自图像入口，不模糊匹配。请求超过 24000 字符时明确按上限分页，保留 continuation，不静默丢内容。
4. 同步、拉取、打开及任务摘要直接返回具体 `pluginSessionId`、`resultRevision` 链接。无成果时只指向准确外部工作；本地推进后旧远端链接仍表明是已保存远端版本，不能冒充本地当前成果。历史核对尊重指定版本；仅缓存链接不声称已核对远端 current，最终 handoff 不以历史匹配冒充当前发布。

页文准备会登记工件，因此 MCP `source_read` 已准确标记为可能写入。后续冷启动 harness 必须在本次明确授权的工具范围内配置调用权限，不能再次把宿主拒绝当成模型失败；本轮未改任何全局审批或 MCP 配置。新入口不会升级旧任务固定包；旧包不支持新 handle 时明确返回能力边界。

主 skill 与 task-api reference 只补实际调用方式与冲突处理。没有追加第二套文档模型，没有要求 Agent 遍历全文 schema、手填哈希或自行创建阅读临时目录。
