# Pair真实DSH工作绑定与接收验证

2026-09-22。本轮从模拟控制器推进到实际DSH profile，验证Workspace、Session、请求接收和持久化去重。使用隔离DSH_HOME、合成HTTP原件服务和固定ReqPilot开发包；远程模型调用为0，不是文档提取语义或真实Pair界面验收。

## 实际路径

`integrations/pair/scripts/dsh-binding-smoke.mjs`通过受支持的`dsh --profile web --patch ...`启动私有环境，不调用被禁止的应用私有bin。`dsh-binding-probe.mjs`只作为该测试profile中的Cordis插件加载，调用真实workspaceController/sessionController和DSH subprocess；不修改Pair源码、生产profile或生产凭据。

- 普通模式：真实创建/重用Workspace及Session，在Session.prompt前拦截。两次启动仍是同一个Session，状态停在START_REQUESTED。
- `--admission`：通过DSH已有LlmAdapter/registerAdapter测试接口注册确定性no-op回复，真正调用sessionController.prompt。第一次接收后故意丢回执，再按同一requestId重试。
- `--recover`：第一轮真实接收后丢回执，改变测试运行地址，再由真实Session日志确认接收；不会再次调用create或prompt。

命令模板：

```sh
node integrations/pair/scripts/dsh-binding-smoke.mjs \
  "$PAIR_REPO" "$PREPARED_PYTHON" "$FROZEN_REQPILOT_BUNDLE" \
  "$NEW_PRIVATE_OUTPUT" --admission
```

输出目录必须是新的私有目录。没有复制生产凭据；关闭会话标题模型调用；测试启动前安装非本地fetch拒绝器。脚本模型只输出“PROBE_ONLY”，不读取/提取原件，也不生成业务成果。不能把该回复当作模型质量证明。

## 实现修正

`TaskLauncher.recoverAcceptance()`新增只读确认路径：仅对START_REQUESTED记录，在既有Session中找到source.kind=user且rpcId相同的持久消息，才将宿主回执补为ACCEPTED。上下文注入、其它requestId或无法读取的日志不能证明接收。确认不改旧workbench地址、原件、能力包或成果。

这只是“接收回执恢复”，不是“文档执行恢复”。没有持久接收证明且端点已变，仍返回TASK_ENDPOINT_RECONNECT_REQUIRED；排队中但尚未形成匹配用户消息的情况，仍走既有重试/重连判断。Agent resume/cancel/事件能力未因此开放。
