## 结论

这次遗漏是需求落实方法的问题。此前以单次运行故障推动局部修复，未持续核对“用户要求→主入口说明→工具/宿主实现→实际成果→验收”。结果是：重要要求写在reference里却未进入操作入口；有代码被当作已接入；合成工件或模型复述被用于支撑超出其范围的印象；精简主稿又删弱了前端入口。

下表核对33个要求面，**不是发现33个缺陷**。明确区分已有且应保留、入口弱化、实现缺口和行为未验。程序测试数量、包哈希、模型退出码均不能替代业务验收。

## 优先缺口与证据

### F01 已有工作台没有成为独立plugin的完整交互入口

原审计证实catalog遗漏、opener参数不足和Sol的实际失败。当前PDF源审阅绑定、自动阶段发布、确认/反馈已真实联调并安装；完整依据传输与其他格式仍待扩展。原失败保留在[工作台审计](Plugin工作台入口与原序保真审计.md)，首轮实现在[接入记录](Plugin工作台接入与反馈闭环.md)，复用同一业务模型与现有界面。

### F02 主稿简化损失核心目标

“短”不能靠删除原序保真、前端和工具入口获得。主稿应明确用户最后拿到什么、阶段怎样查看、全文怎样不丢、什么反馈会触发下一步。技术语法可以下沉，但业务要求与可执行入口不能消失。原候选留作失败/改进证据，不直接发布。

### F03 图片手册存在相反方向的说明

审计时`tools-images.md`开头要求辅助图归其条款/表格；后段却写“Preserve supporting or non-normative graphics as NON_REQUIREMENT”，放在compile-images输入说明中，会引导单独建SRC。职责skill又要求compile-images只用于真正独立的图。

代码已有表格关联图片排除/归属能力，不能据文字冲突断言所有含图表都会错误输出。开发稿现已统一：表内/条款辅助图走所属条目与释读，真正独立图才进入独立图条目流程；校验原图、归属、释读与推断分别做，不能只数媒体文件。

### F04 既有授权原则被误当成新待决策

`reqpilot-review/SKILL.md`已写“an explicit end-to-end request can authorize it without per-item permission”。前轮理解测试后，我又把普通任务拆分授权笼统列为待用户定义，遗漏了这条已有规则。应传递原任务已有授权；只有当前请求确实没覆盖的范围才补充决定，不能反复索要已给的批准。结构版本确认与逐条拆分许可也不能混为一事。

### F05 拆分处置的覆盖与理由——历史复现，后续已修

当前代码已实现dispositions、KEEP/UNDO理由与review_scope的授权/剩余范围，部分提交为PARTIAL；新版review/verify skill已按实际字段自查。下面保留最初失败原因和回执，不能继续要求生产Agent绕开已经修复的缺口。

对五页合成SOR的13条需求声明完整授权范围，只提交一条KEEP。程序接受部分提交本身正确，但输出artifact `status=COMPLETE`、`kept_source_ids`仅1项，没有未检查范围字段；输入KEEP理由不在输出工件或编译回执中。CLI目前只检查decisions是authorized的子集，核心status根据已有拆分proof/过期状态形成，不表达全授权范围进度。

因此需要分别表达“已提交范围编制成功”与“本轮授权范围审查完成”，并保留KEEP/UNDO的理由和有效范围，允许中途保存而不伪装全范围完成。不能靠强制第一次交齐全部结果来修。

证据在 `prototype/runtime-data/requirements-audit-20260912/partial-keep-probe.json`，未改客户数据。此前Sol v2实际是12个KEEP和1个SPLIT，本例没有漏掉其余12条；这不消除上述状态和KEEP理由的通用缺口。

### F06 无知识库不等于停止源内审查

目前无依据跳过符合性分析有实现，策略交接已修。仍须明确：入口发现内部依据状态未知时及时确认；没有产品依据时继续检查客户原文的矛盾、缺附件、TBD和不清楚的判据。不能生成整表PENDING_EVIDENCE，也不能把所有“分析”都跳过。规则在review/J08–J09中已有；普通未预告KB状态的真实任务与结构化问题交付尚需行为证据。

### F07 历史扫描/混合PDF经验不等于当前插件已迁移

历史QC/T有双OCR、像素核查及转写归属；当前capture明确无OCR，capture-pdf-text只是PDF文字绘制流补读，README也明确不承诺OCR→SourceIR补充。通用PDF/看图可读与高保真结构化写回是两件事。已有定位不应重做；应验证当前入口能否把正确读到的内容绑定、保存、修订并导出。尚未完成的形态必须保留可定位缺口。

### F08 有31条说明，仍缺几种关键完整操作示例

### F09 机械字段仍压给Agent
