## 实现组成

- `documentWorkCatalog`负责当前文档工作列表的读取和身份校验；`DocumentWorkPicker`在公共外壳与文档台账复用。只在打开选择入口时取列表，失败保留本范围已经读到的内容。
- `documentWorkSelection`新增每个插件会话的查看版记忆；`DocumentWorkSurface`负责切换和共享反馈范围请求。
- `ExternalAgentPanel`、`SourceRequirementNodeLens`和`NativeStructureReferenceDock`收拢插件新反馈入口。历史版可以保留草稿，服务端提交能力仍以真实版本与capability为准。
- 公共工作区移除旧阅读器底部的通用技术说明及“当前反馈能力”宣告；真实能力与不可用原因由对应动作／协作区表达，避免在插件历史版旁宣称原生修订可用，也释放正文高度。
- 重点标记确实未提供或读取失败时显示“—”及对应说明，仅实际读取中显示省略号，避免把不可用信息伪装成持续loading。
- `KnowledgeWorkspace`／`ProjectKnowledgePanel`／`projectKnowledge`提供项目资料目录及分析选择。可读取和可证明符合性分开，未知authority、用途、适用性保持未标记；明确失效文档不自动打开其他文件。
- `useSourceItemReasoning`仅对analysis加入依据范围，不改变decomposition请求。选择按项目、客户文档、原文基线保存。下次运行范围与既有建议的事实引用分别显示。

- 外部插件尚未公开start／steer／interrupt／resume控制能力，UI不制造可运行按钮，也不将保存反馈说成唤醒模型。新项目依据选择目前接入原生分析；插件重分析仍依宿主传输合同。

- 项目资料的权威、用途和适用性显示已有登记值；完整的元信息维护入口、插件分析范围设置和所有历史阶段共用reader尚未完成。
