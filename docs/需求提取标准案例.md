# ReqPilotX 需求提取案例原则

更新：2026-09-20。原稿包含真实客户案例、逐字内容与私有目标答案，正文保留在私有资料中，本源码基线只保留可复用原则。当前模型以[模型 V1](需求提取/文档结构与原文条目模型V1.md)和[分类 V1](需求提取/分类与验证关联规则V1.md)为准。

## 结构与粒度

- 从授权原件建立全文概览，按语义范围精读；始终允许回看相邻章节、原页、表格、图像和引用。
- 文档单元、章节与内容递归组织；章节包含关系、需求派生和上下文引用分别表达。
- 有意义的原文全部保留。纯标题以结构呈现；正文、文控、参考、定义等按内容角色保留，不因非需求而丢弃。
- 有编号正文默认识别到最小有意义层；完整 BOM、一个试验的组成/条件可保持整体，并保留内部编号、顺序与成组理由。
- 不按页、句号、物理行数、单元格数或 token 窗口自动决定业务边界。

## 来源与呈现

- 原文语言、条件、数值、单位、否定、例外、缺号、重复编号和矛盾不得静默修正。
- 逻辑表保留表头、合并值、表注、跨页续接及嵌入图片；物理片段不能冒充多个独立总表。
- 真实 1:1 的结构与条目在工作台/Excel 共用一行，1:N 才展开；直接正文和子结构严格保持来源顺序。
- 图片释读、摘要、翻译和派生表达独立标注，不冒充客户逐字原文。
- 共享条件通过准确来源关联复用；不得把章节概述机械附到全部后代。

## 派生、版本与验收

- 先保留完整原文基线，再在明确授权范围进行工程派生，原文父项与双向追溯不删除。
- 原文包含关系不等于需求派生；SRC/REQ 身份不等于原文阅读顺序。
- 修订只影响明确对象，保留有效人工意见、旧版本与不可变来源；不能用重放旧候选覆盖新成果。
- 结构完整、程序校验、模型自然完成、源语义正确、人工接受和正式交付分别判定。
- 旧案例数量和人工答案不进入新任务输入，也不冒充独立留出集。

可分发的完整合成方法见[PDF 策略与粒度正反例](需求提取/PDF处理策略与粒度正反例.md)。真实案例取用见[资料边界](源码与私有资料边界.md)。
