# Source reading and document structure

Use the evidence route appropriate to each page/region. Document genre and physical encoding are separate: an ISO-like layout can be native, scanned or mixed. Preserve the original; a repaired reading view is not a replacement source.

## Role and structure

| Case | Normal handling | Evidence that changes the handling |
|---|---|---|
| R01 Front matter and source role | Covers/contents/document control remain whole structure; contents support navigation, while body headings establish actual clauses. Use the supplied customer/internal/review role | A cover-page confidentiality or delivery obligation needs its actual body range. An engineer Matrix, annotated review or similarly named spreadsheet is not automatically an original/gold pair. When one block mixes navigation and body, use v2 exact ranges if supported; older-host gaps remain explicit rather than suppressing the whole block |
| R02 Headings, direct prose and attachments | Preserve recursive ancestors, parent body, introductory/trailing text and true order. Join separately captured number/title fragments only with source support. Attachments belong where the source establishes ownership, including beneath a numbered item | A numbered cross-reference at the start of a wrapped line is not a new heading. A genuine new numbered peer remains a peer even in one block. Independent document restarts can be sibling units, but “Appendix” alone does not detach a real annex. Preserve duplicates, missing numbers and printed-but-empty clauses; do not synthesize absent numbers |

## Reading evidence

| Case | Primary route | Change condition and retained evidence |
|---|---|---|
| R03 Native text is readable | Positioned text plus native table topology; compare rendered pages where order/coverage is suspect | Multiple columns, rotated pages, split lines or table text in paint order need visual reading-order repair. Use actual page transforms/printed labels, not fixed offsets. Bounding boxes alone do not prove semantic ownership |
| R04 Full-page scan or invisible OCR layer | Rendered source pixels with OCR as a candidate; inspect numerals, units and boundaries | A selectable hidden layer can be wrong or incomplete. Agreement of two OCR engines is not source proof. Preserve original pixels and corrected transcription separately; uncertain glyphs stay unresolved |
| R05 Vector glyphs, bad Unicode, mixed PDF | Combine visual text recovery with usable native table geometry and original images | Do not rasterize away good table topology or substitute garbled text to satisfy coverage. Missing text, missing grid and uncertain ownership are different gaps; report their specific ranges |
| R06 Watermarks, repeated furniture, blank pages and overlays | Keep the original page; separate repeated page numbers/company marks from body items after checking position and role. Verify apparent blank pages visually | Repeated stamps can overlap real text; a front-page duty is not furniture. Empty extraction does not prove a blank page. Separate PDF annotation objects from formal body; attributed review comments do not silently amend it. Visible body remarks/columns remain source content; authorized marked-up revisions retain their declared authority |
| R07 Bilingual or multi-version content | Keep both source-language spans for one genuinely corresponding item, using only the document's declared language precedence | Different limits, references or paragraph mappings require conflict review, not two automatically duplicated requirements or a blended translation. A revision log describes changes but cannot supply missing old values; complete versions retain distinct source identities. Identical duplicate files share a source identity, but preserve distinct placements/references; repeated wording in different scopes is not sufficient to merge items |
| R08 Diagrams and engineering notation | Read the original at sufficient resolution, including caption, arrows, labels, axes, legend, units and exclusions. Attach supporting figures to their actual clause/table; independent normative figures can be whole image items | OCR text does not capture arrow direction or topology. Check diameter/thread/parentheses and reference dimensions; do not invent tolerances. Distinguish visible facts, Agent interpretation and suggested implications. Full drawing/GD&T derivation is not proven merely by preserving the drawing; keep unsupported details locatable and explicit |
| R09 Referenced files or unsupported formats | Preserve the attachment/reference and inspect supplied content using actual capabilities | An attachment icon is not its file. Missing standards or unread objects cannot supply parameters. DOCX/XLSX keep paragraph/table/cell locators and original assets; conversion must not invent PDF pages or replace the original SHA. Existing Office capture support does not imply every review/UI path is complete |

Escalate only affected unclear regions: original page/crop, alternate capture or source-linked manual transcription as supported. Retain locator precision honestly—page, figure, approximate cell and exact text range are different. A correct boundary that the tool cannot encode needs an implementation fix or explicit gap, not a shortened/distorted source statement. Continue usable scopes without declaring unread regions covered.

Close a requested section at the next actual peer or higher-level heading in the original. A parts table at a page end can be followed by definitions, constraints or a legend on the next page; include that continuation. Conversely, do not absorb the following section merely because it shares a page. Verify the boundary visually when native heading text is missing; neither search results nor an earlier example's page range establishes completeness.

For a numeric value, short line or table detail, `source_read(view:"image", page:..., bbox:..., scale:...)` exposes the existing native PDF crop renderer. Use visible PDF coordinates from the original locator, not PNG pixels; scale is at most 4. Keep enough surrounding context to interpret the crop. These source-pinned pixels do not require OCR or rebuilding every page view, and do not change the selected business result.

## When a PDF toolkit reports success

- A page with a logo and no text can contain outlined vector letters, not a scan. A scan can already contain a bad hidden text layer. Check actual visible body coverage; neither nonzero text nor a toolkit's page-type label establishes it.
- For formal-body OCR, use a rendering without review annotation icons when available, retaining attributed annotations separately. Icons can cover a title or number. Honor an explicitly authoritative annotated revision; do not erase its meaning.
- Keep full scoped text, source page images and structured positions together. A reading-order preview may truncate text; a detected table may be a page border or several unrelated grids. Check row/column structure and supporting figures against the original before adopting them.
- A more fluent second OCR pass can still change a limit or inequality. Compare critical values and governing context with pixels, keep the raw candidates, and revise only supported differences. Toolkit completion and coordinate validation do not establish source fidelity.

## Use the available reading tools to save usable source

When the current tool catalog supports it, use `source_prepare` with `mode:"ocr"`, the current task/revision and explicit `pages`. The program renders, recognizes, saves and returns ordinary authoring refs; do not assemble SourceIR or coordinate IDs by hand. `profile:"numbers"` adds localized numeric alternatives without applying them. `profile:"tables"` needs `table_regions`: select an actual captured table `source_ref`, or one original `page`/`bbox`; give `header_row_count` only from the source. These are physical reading regions, not business split decisions. The ruled-table route does not establish borderless-table topology.

Follow the result's `source_authoring_read`, or a table's `table_reads.cells` and `original_image`, directly. These requests bind the exact capture, public cell view and original crop; inspecting raw `source_ir.json` field names is unnecessary.

Inspect the original image when OCR differs, loses a comparator/unit, or gives an incomplete cell. `source_transcription_revise` records `changes` against a `ref`, or same-page `refs` for a complete multi-line transcription. Supply corrected `text`, or existing `cells` with `row`/`column`/`text`, and a source-review `reason`. It preserves raw OCR, geometry and the old result. A new reading revision does not itself revise existing items: use the returned refs in a bounded `map_apply`, then ordinary item compilation or the existing affected-scope revision.

In a script host the equivalent commands are `read-pdf-visual`, `capture-visual-source` and `revise-visual-text`; use the installed CLI's help and JSON input files. If these capabilities are absent from that fixed package, retain the exact gap and use available original-image reading; do not invent tool names or relabel an entire image as extracted numbered clauses.
