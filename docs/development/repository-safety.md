# 可分发源码检查

提交前检查实际暂存内容：

```bash
git add <本次已审查的具体范围>
python prototype/scripts/repository_safety_audit.py --staged
git diff --cached --check
```

不带参数检查当前工作区，`--staged`读取Git索引内blob和同一索引内的例外表；因此修改工作副本不会掩盖待提交的旧内容。CI在checkout后使用索引模式。私有标识表如需参与本机检查，通过`--blocklist <私有文件>`显式传入，不提交该表。

运行数据、私有评测、数据库来源目录、依赖和构建产物不能通过强制暂存绕过检查。源文档二进制拒绝；脚本、TSX/JSX、模块JS及锁文件均进行文本模式扫描，超预算文本会失败，不静默视为安全。

公开品牌、上游署名、故意构造的无效凭据测试等实际误报记录在`prototype/contracts/repository-safety-reviews.json`。每项必须有理由、允许的具体规则和完整文件SHA-256；内容变化后失效。合成标签本身不构成豁免；禁止路径和文档二进制不能通过此表豁免。

这是已知私有内容、目录和凭据模式的提交检查，不能替代新资料来源审查或承诺任意数据绝对无敏感内容。历史扫描使用`--history`且单独处理；净化最新文件树不等于清除所有远端引用和既有历史。
