# SRC / REQ 编号与显示顺序方案

更新：2026-09-09。用户要求解决编号顺序；本文给出推荐方案，**未执行既有号码迁移**。原文身份和退休号码不复用仍遵守[模型V1](文档结构与原文条目模型V1.md)及已实现的[编号水位与重放](原文编号水位与历史重放.md)。

## 1. 四件事分开

| 字段职责 | 含义 | 变化规则 |
|---|---|---|
| 原文编号 | 客户写的 4.1.2、a)、试验 7、BOM 行 3 等 | 原样保留缺号、重复和倒序；不根据系统编号修正 |
| 稳定对象身份 | 反馈、来源、派生、响应、引用所绑定的对象 | 不因排序、筛选、折叠、导出或换显示名改变 |
| SRC / REQ 可见业务号 | SRC 覆盖全部有意义原文条目；REQ 表示需求子集 | 推荐首次按原序分配，REQ 复用相应 SRC 数字后缀；后续已有号稳定、退休号不复用 |
| 来源顺序 / 视图行号 | 在已恢复的原文树中如何阅读；当前视图第几行 | 来源顺序可因有依据的结构纠正而调整；行号可随范围变化，但不冒充原编号或业务 ID |

封面/目录/文控整体和纯章节标题不为凑连续号码制造SRC；原文完整保留在结构内容中。需求类别和非需求角色不是编号来源。Snn 属于显式工程派生，原文原有编号子条款不得借 Snn 代替。

## 2. 推荐分配与排列

1. 新文档先形成可核对的结构和统一来源顺序，再给首次完整条目基线分配 SRC。临时候选可以使用内部临时身份；未发布号码不作为稳定用户引用。不可按“先处理完全部文本、再处理全部表格”的执行顺序发号。
2. 顺序以文档/附件顺序、真实包含关系及范围内阅读顺序为主；页与坐标辅助，不能只按页号或字符串编号排序。先修复错误归属，再排序；跨页试验按完整业务范围显示一次。
3. 首次 SRC 从文档编号域内按该顺序分配；需求项 REQ 采用同一数字后缀。例如 SRC-0001 是说明，SRC-0002 是要求，则对应 REQ-0002。REQ 缺 0001 是正常子集，不是漏提取。
4. 后续修订已有条目保持号码；中间新发现的条目用水位后的新 SRC，放到正确来源位置。不会为让画面连续而重编号其后所有对象。新增 REQ 判断使用原 SRC 对应后缀并记录判定版本；转非需求保留历史 REQ 关联，不挪作他用。
5. 拆分/合并原文范围按既有来源修订与 lineage 合同处理，不能把旧号偷偷换给无关内容。新增身份、保留身份和退休关系须可追溯。
6. 派生项放在其来源父项之后，并保存独立派生顺序；稳定 Snn 与呈现顺序同样分开。保留整体与已拆分有明确处置，不能从“没有 Snn”推断已经检查。
7. 前端与 Excel 共用来源排序和同一版本。过滤保留必要祖先上下文；折叠不隐式改变导出范围。导出全部/当前筛选范围需明确，不以渲染出来的 DOM 行数决定业务集合。

## 3. 具体例子

首次基线的原文顺序为：1“背景”、2.1“接口”、2.2“日志”。对应 SRC-0001 / SRC-0002 / SRC-0003，需求为 REQ-0002 / REQ-0003。

后续在原件中发现夹在 2.1 与 2.2 之间、此前遗漏的一个有意义条目，分配 SRC-0004。正确阅读顺序变成 **SRC-0001 → SRC-0002 → SRC-0004 → SRC-0003**；旧 SRC-0003 的意见、引用、历史 Excel 仍然有效可追溯。若需要画面连续，可以增加“序”列 1/2/3/4；不能让同一 SRC-0003 变成另一个内容。

## 4. 需要连续号码时的选择

稳定可引用业务号与“每次修订仍按原序连续”的显示号无法在中间插入/删除时同时由一个字段满足。**推荐保留稳定 SRC/REQ，并把连续行序作为阅读辅助。** 这能解决首次编号乱序和 UI/Excel 排列不一致，不承诺修订后 SRC 数字总是单调递增。

如果产品最终要求 SRC/REQ 标签本身每版都连续，需另设带版本的显示号码映射，底层引用只用稳定身份；旧版导出、反馈、外部引用和搜索必须能反查。该选择需要明确产品决定和独立迁移计划，不能在这次文档整理中默认改掉历史号。

## 5. 验收例

- 文本、表格、图片交错的新文档，首次 SRC 按共同来源顺序分配；REQ 是对应子集。
- 原编号重复/缺号/倒序不丢内容、不自动更正；排序不把 10 排在 2 前面。
- 中间补项、删除/撤销、非需求转需求、原范围拆分/合并后，现有身份可回溯、退休号码不复用。
- 多页试验和含图表格不因资产或物理片段顺序产生重复号码。
- 同一版本/相同导出范围下，UI 与 Excel 的对象序列、父级、主类型、SRC/REQ、原编号及响应一致；当前视图行号不参与引用和判断。

旧水位修复已有历史重放证据，不因此推断本方案的新文档发号、全部修订和显示顺序已完整实现。实施列入[开发计划](开发计划.md) P1b。
