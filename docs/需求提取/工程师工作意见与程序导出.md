# 工程师工作意见与程序导出

原生 SourceItem/Snn 工作台使用独立工程师工作意见，不依赖旧 RequirementSet 锁定，也不把分类 `USER_OVERRIDE` 当作技术结论。意见属于当前版本的工作状态，不自动构成正式客户批准。

## 共享合同

`source_item_manual_decisions.py` 从已验证 Map、完整原表、SourceItem、派生和图注构建 `source-item-manual-context/v1`。每个实际分析单元绑定 `unit_context_sha256`；正文、准确来源、分类、共同条件或派生依据变化会影响该指纹。纯 Map 节点/表 scope 显示身份变化不单独使意见失效。

`source-item-manual-decisions/v1` 保存用户判断、理由、适用条件、证据请求，以及来源版本、前驱 SHA 和历史记录。`CURRENT` 人工意见优先于 AI；AI 工件和建议保留。撤回为 `WITHDRAWN`；来源或上下文变化为 `STALE`。即使旧原文随后恢复，`STALE` 也不会自动复活，必须由用户明确重新记录。单次用户保存直接继承真实已存储前版，不产生未落库的中间前驱。

原生发布不接收模型包里的人工记录。发布事务在相同文档/来源锁下读取用户仓库最新记录，再按实际前后上下文保留或失效，避免覆盖 Agent 运行期间用户的新编辑。历史发布没有可验证前版上下文时保守失效，记录 `MISSING_PREVIOUS_CONTEXT`。Map-only 更新尚未形成可靠 SourceItem 后继时也不能声明原意见已确认有效。

## 原生 API 与界面

`GET/POST /api/projects/{project_id}/sor-documents/{document_id}/agent-structure/delivery/engineer-responses` 供用户界面读写。POST 必须携带：

- `command_id`、`expected_source_sha256`、`expected_baseline_sha256`、`expected_response_revision`；
- 每条的 `unit_id`、`expected_unit_context_sha256`、`action: SET|WITHDRAW`；
- SET 的 `decision`、`reason`，以及可选 `conditions`、`evidence_requests`。

服务器确定 `USER_INPUT` 和时间戳；原生 Agent 动态工具没有人工写入操作。重复命令幂等，变参复用拒绝，过期版本返回 409。PostgreSQL 使用 `0036_source_item_manual_decisions.sql` 的追加版本表，正式数据迁移由应用现有迁移器执行。

无人工记录时 `/delivery/state` 保持 PDF 轻量读面，`engineer_responses` 为 null；展开工程师意见面板时才按需加载准确单元上下文。已有人工记录时，读面使用同组 Map/基线/图注/派生/AI 状态；读取期间版本变化会要求重试，不把新意见叠加到旧条目。只读 API 不创建一个未存储的响应后继。

当前编辑字段在保存失败时留在页面；未保存草稿尚不保证刷新或切换条目后恢复。已保存意见和历史由用户仓库持久化。

## 程序 Excel

`build_delivery_snapshot(..., manual_decisions=...)` 复用同一 typed Matrix 结论合同；默认无此参数时不增加 manual 元数据或改变旧快照值。原生 raw-source-graph 和常规基线均进入此共享路径。导出可同时钉住基线、响应 revision 和 `business_basis_sha256`，防止旧页面导出另一组派生/AI/用户意见。

当前人工结论进入主表判断列，理由、条件、证据请求进入说明列；原 AI 建议明确保留。人工与 AI 合并超过 Excel 单元格限制时，完整人工意见留在主表，完整 AI 建议通过现有“完整内容”列导航到按顺序无损分段的详情区。原文、SRC/REQ、派生、原表和来源链接不被意见替代。导出由内部程序完成，不增加运行时模型逐格阅读、重新提取或重新分析。

## 可复用插件

程序导入只消费用户明确提供的决定文件，详见 [人工意见导入合同](../../plugins/reqpilot/skills/reqpilot/references/manual-decisions.md)。导入回执保存输入副本与 SHA，后续 review 验证按真实前驱复演。该回执证明程序输入与结果一致，不是身份认证或正式批准；不得把模型自行决定的内容标成用户输入。应用以自己的用户仓库为权威，不信任模型通过任意文件或 inline JSON 增删人工意见。

## 已验证范围

聚焦自动化覆盖人工优先/AI 保留、撤回、变化与恢复不复活、真实前驱连续、并发 CAS/幂等、读面混版拒绝、原生图谱合成分支、PDF→用户导入→review→程序 XLSX，以及超长人工/AI 无损显示。隔离 SQLite UI 使用程序生成 PDF；原生图谱测试模拟 job discovery，实际复验 typed graph、原表与导出。独立 PostgreSQL 验证覆盖跨进程竞争、发布事务回滚和最新用户意见保留。

真实 E01/PDS 不写合成人工意见。浏览器证据、隔离 PG 回执与具体运行结果保存在 ignored `prototype/runtime-data/agent-loop-20260908/manual-*`；这些验证不等于真实用户意见或正式客户接受。PDF 正式任务恢复与该能力最终发布状态由当前开发计划/运行记录另行记录。
