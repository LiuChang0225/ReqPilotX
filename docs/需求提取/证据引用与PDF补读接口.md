# 证据引用与PDF补读接口

2026-09-11。接续Sol/Luna对照中确认的两个表达断点；用户最新配置为Sol high、Luna max。本轮复用既有Map、SourceIR、定位、版本与编译路径，不改原件、不批量改旧结果。

## 核对证据不再生成业务范围

Map编辑的节点可用`evidence_refs:[{source:<已有索引或ID>,row_range:[lo,hi]}]`保留核对来源。v2决定文件使用`source_node_id`；编译后进入既有Map节点的可选`evidence_anchors`。复用来源定位与表格行/合并范围检查，引用可在紧凑核对文件中直接读取。

该引用不进入`source_content`、`logical_tables`或条目请求，不将被引用范围记作已处理内容，也不改变所属节点的正文顺序/页码。真实业务表及其合理子条目继续使用原有关系；没有按重叠或role关键字自动删除表格。紧凑核对视图现在明确显示：每个逻辑表都会创建表格提取范围，role标签不会自动变成“仅供核对”。

在原B-Luna草稿的工程重放中，将布局表明确转换为两处证据引用后，原文内容完全不变，额外表格提取请求由1变0。原模型工件保留；此结果不是Luna新成绩。

## 原PDF补读进入可验证的新捕获文件

`capture-pdf-text`接受原PDF、当前SourceIR、原页、可选查询及新输出目录，读取原件文本绘制记录。按实际基线分开文字段，仅连接同基线相邻片段，不将不同列/行拼成一个句子，也不填入模型臆写的替换文字。该入口不是OCR，不承诺解决所有编码和扫描问题。

新文件保留所有旧节点、索引、资产与基座捕获身份，追加带`pdf_text_trace`来源记录的节点；具体版本由文件哈希区分。新节点身份由PDF绘制读取器版本与实际定位派生。观察记录标明`REQUIRES_ORIGINAL_REVIEW`：文本对象存在不等于所有像素可见，裁切/遮挡仍需回查。旋转页位置转换到已有可见页坐标。

使用返回的新`source_ir`与旧`map_dir`即可局部修订。普通捕获差异仍拒绝复用索引；只允许经原件重放核验的追加观察。编译器检查文字、字形片段及定位，拒绝改写的观察；调用者不重算ID、字符偏移或哈希。应移除旧的重叠内容选择，保留同一旧块中属于其他范围的文字。

原B-Sol工程重放已从原PDF补回遗漏的项目符号和标点，成功绑定为新Map内容。原件和旧捕获字节不变，新Map保留文字对象来源及可见性待核对标识；没有将遮挡文字伪称为视觉已确认。
