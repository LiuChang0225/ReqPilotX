## 本轮发现与经验落点

| 现象与原因 | 实际处理与可复用方法 |
|---|---|
| 旧版首次导出后还要制造无内容变化的 candidate 才能收尾 | 92411 的交付自动登记已被两次 Sol 实际使用。路径、复制、校验、回执由工具处理，不再让模型拼装机械收尾 |
| 请求关闭子 Agent 的旧 flag 没有阻止实际调用 | 本轮私有 launcher 增加实际识别的 `agents.enabled=false`，再检查公开调用记录；不能仅按启动参数宣称单 Agent。debug prompt 不暴露完整工具 schema，该边界如实保留 |
| 新原件目录与正文出现相同跳号，诊断 ID 冲突使结构候选失败 | Sol 自行使用 capture-only 保留原始来源后继续。运行后将诊断身份纳入父级和两端节点作用域，resolver 升至 2.48.1；完整 capture 已直接复验通过，两处警告均保留。无需扩大 skill 或让模型替程序去重 |
| 新表详情缺列头，但源表、共享 header IDs 和 Excel 正确 | UI 任务修复局部表投影：按选中内容的各段取最近表头组并去重。实机恢复列头、表内图片与完整 BOM，未修改模型成果 |
| HTTP Excel 标题显示内容摘要文件名 | 应用导出入口已显式传入登记的原文件名，共用 exporter 已有对应参数，14项回归及实际下载通过。展示名与存储路径分开，不能据此断言前边提取映射错误 |
| 需要核对项目依据原件 | 新增按项目/文件与来源 SHA 校验的原件 GET，支持 Range；UI 已实际打开 PDF。读取证据与生成符合性结论仍分开 |

核心分工继续保持：skill 说明任务目的、判断原则与读取入口；Agent 调查原文、决定语义；脚本自动选址、编制、编号、校验及导出；工作台显示相同成果并接收可选反馈。新增程序缺陷优先修工具，不用更多提示词要求模型长期绕行。
