## 本轮已实现

| 工作面 | 当前行为 |
|---|---|
| 响应分析 | 保留 record table 与 filter bar；按实际分析单元计算待处理、待内部证据、待澄清、偏离和人工意见。派生存在时不重复计父项。筛选直接定位命中派生单元，同一父项逐个处理后再进入下一原文。 |

| Agent 协作 | 原生公开消息 start/delta/completed 经 SSE 呈现；最新回复优先。连接、回复中、回复未完成、任务结束分别表达。结构确认/可核对成果置于消息之前，活动详情留在同一协作区。 |
| 交付版本 | 保存当时完整矩阵快照与程序生成的 Excel。历史下载读取已保存对象，不从最新工作版重算。草稿可包含未决项；FORMAL 要求本版有效响应齐备，并明确接受指定快照。工作版仍可继续修订。 |

采用现有 `RequirementMatrix` 有效结论规则、原生来源/分析/人工意见合同及 Excel renderer。未要求所有结论都为“符合”，也未把逐条人工审核添加为前置条件。正式交付的锁定是产品内的快照接受，不代表客户接受或外部签署。

## 协议与保存边界

- 公开增量以 attempt/thread/turn/item 身份和单调消息版本合并；item/completed 的完整文本作为最终值。推理通知继续禁用，推理内容不进入日志或页面。
- `runtime/messages.json` 是可恢复的公开消息物化视图；JSONL 仍为回放依据。SSE 按字节游标续接，支持 `Last-Event-ID`，终态补齐后关闭。原事件 GET 保持可用。
- 迁移 `0037_source_item_delivery_versions.sql` 为原生交付增加只追加记录。保存使用共同来源锁、精确快照/业务依据校验及命令幂等；文件经 object store 按 SHA 验证。历史读取同时核验快照和 Excel。
- 参考：[Beautiful UI](https://www.beautifului.dev/) 的 record/filter table 与任务区层级；[Codex App Server 官方协议](https://learn.chatgpt.com/docs/app-server) 的公开消息增量与终态完整 item。
