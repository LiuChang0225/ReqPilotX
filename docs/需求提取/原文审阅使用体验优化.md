# 原文审阅使用体验优化

更新：2026-09-07。状态：已接入主应用，完成当前PDS工作版浏览器核验。本文记录审阅操作改进，不代表全文语义验收或自动提取能力全部完成。

## 已落地的工作面

继续使用原文树、条目内容、PDF对照的现有工作台。用户首先看到客户原文、已有派生和图片释读；分类依据、共享上下文、运行轨迹按需展开。全局分析数量留在全局操作面，不在每条需求上重复。

| 使用者要完成的事 | 当前入口与行为 |
| --- | --- |
| 找到具体要求 | 树顶部按SRC/REQ、标题或绑定原文全文搜索；`/`进入搜索，回车定位首个匹配；下一项遵循筛选后的原文顺序 |
| 找到优先分析区域 | 条目显示技术参数/试验验证提示，所属章节汇总重点数量；提供重点及两类细分筛选 |
| 只看某类、某主题或待核对项 | 类别、主题、审阅范围独立组合；保留真实祖先路径，允许手动收起；清除后恢复完整原文 |
| 查看已拆好的需求与变更 | 条目首部直达派生、图与释读、本次变化；变化展示前后判断，不把仅改写理由当成内容变化 |
| 提出修改 | 首部固定入口、内容栏下沿可收起编辑器；已发送反馈与本机草稿分开；切换/刷新可恢复草稿 |
| 核查表格与图 | 放大本条默认显示继承表头、共享值和当前内容；切换完整原表后仍定位本条；原图和Agent释读分开 |
| 看清PDF | 按宽度放大、循环聚焦当前框标；宽屏阅读临时收起PDF，随时恢复对照 |
| 接着分析或导出 | 左侧需求分析、矩阵导出读取同一原生工作账本；显式历史Requirement Set保持旧入口；工作草稿无需先生成旧式确认清单 |

## 重点提示的含义

技术参数与试验验证是审阅优先级提示，沿用[分类与验证关联规则V1](分类与验证关联规则V1.md)，不新增需求类别。它不等同于不符合，也不等同于待澄清问题。法规、标准、物流包装等主题仍独立筛选。

标记来自绑定来源SHA、基线SHA、条目身份的语义审阅索引，见[索引接口](原生审阅上下文索引接口.md)。前端不因文本中有数字、单位、周期或标准号就自动认定技术参数。无重点标记或仅部分覆盖时明确显示覆盖未知，不能以0推断没有重点。

当前PDS v27有449 SRC、341原文需求、108非需求内容、58派生项。263 SRC标记重点：技术参数52、试验验证213、重叠2。24条需关注与263条重点是不同集合。存在内部证据缺口不自动把全部380分析单元都塞进待核对筛选。

## 草稿与操作边界

- 草稿按项目、文档、SourceItem、基线隔离在本机保存；跨版本只允许显式取回，不自动转成新版本反馈。存储失败提示仅页面暂存。
- 晚返回的保存请求只清除其实际提交的草稿，不能擦除用户后来输入或其他条目的内容。
- 文字反馈支持保存并交给Agent做范围修订。表格支持保存反馈及分类复核；当前自动范围修订只支持文字，表格行组/拆合边界尚未接通。
- 重点索引只读；本轮UI核验没有向真实PDS提交测试反馈、启动分析或重跑模型。真实基线仍为v27 `5c98e589…`。
