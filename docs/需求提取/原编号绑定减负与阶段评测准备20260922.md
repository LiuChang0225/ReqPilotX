# 原编号绑定减负与阶段评测准备

2026-09-22。接入编号短引用、所属标题的精确编号投影，以及预制 Map 上的初次条目评测准备。旧客户原稿、源图、判据、答案与固定包保持私有，不进入源码或改变历史成绩。

## 编号与来源合同

- 条目读取提供 `numbering_review`，`part:numbering` 列出当前原文段、所属标题和短引用。它们只说明位置，不自动判断某个数字是不是原编号。
- `ITEM_SOURCE + segment_index` 选择读取返回的原文段或单元格开头；`ITEM_HEADING + heading_ref` 选择所属标题。程序换算真实 ID 和绝对偏移，再由既有编译器验证来源、归属、完整编号与范围。
- 原文内部编号仍使用已有精确引用及 extent。多编号在 `source_numbers` 内保存，不为编号拆开完整 BOM 或生成派生项；显式清除、原文、分类和边界继续保持。
- 当历史 Map label 包含整个标题时，允许选取实际所属标题中经既有编号语法确认的完整数字前缀；仍限制首个直属正文条目，拒绝截断、错误位置和跨条目绑定，不重写 Map。
- 无内部产品知识只意味着不做符合性结论，不能省略原件定义、条件及适用范围。既有 context 入口提供候选，实际关联仍由 Agent 判断。

实现维护源在[共用引擎](../../packages/engine/src/reqpilotx/application/agent_workflow/source_item_visual.py)和[短引用适配](../../plugins/reqpilot/scripts/task_numbering.py)。产品指导从 `agent-assets/current/plugin-skills` 维护，同步至插件发现目录；旧冻结包通过 capability 检查拒绝不支持的入口，不会被自动更换。

## 预制 Map 阶段输入

`MAP_BUNDLE` recipe 固定输入目录及逐文件哈希，经现有工作区验证器登记明确的 `eval-map-seed` 操作。只引入 Map/来源工件，不复制旧 operation 回执，不伪造模型或编译执行。源码内测试使用独立生成的合成 PDF 验证登记后能够实际生成新条目，并拒绝输入篡改。

运行和报告记录 `STAGE_FIXTURE`、`provided_stages`、`PREPARED_INPUT_STAGE`；`prior_answers_supplied` 如实反映阶段工件已提供。预制 Map 不是本轮模型成果或免检 gold，不计本轮 Map 能力；编制、编号、上下文、来源语义和同版交付分别复核。Map-only 准备使用通用 `grade` 及来源评审，`grade-stage` 只用于已经提供 Items 的关系复核。

私有案例通过既有 `REQPILOTX_AGENT_EVAL_CASES` 指向授权目录的 cases JSON，再由显式 bindings 指定原件、recipe 和 oracle。默认源码案例目录不导入客户范围、固定答案或私有路径。已有私有原件/判据继续使用原哈希；新运行须重新冻结候选包与输入，不能重标旧运行。
