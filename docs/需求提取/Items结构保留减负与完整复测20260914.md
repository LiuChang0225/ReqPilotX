## 已实现

`items_apply.decisions.retain_map_structure=true` 让程序保留 Map 已标定的标题及整块 COVER/TABLE_OF_CONTENTS/DOCUMENT_CONTROL。Agent 继续提供正文、业务表格的真实选区、分类、分组、key 和 label。不是按文本关键词、页码或表格行数猜业务角色。

- 自动补齐已提供文字 scope 中可证明的未覆盖标题；自动添加未提供的纯标题和完整前置材料 scope。
- 普通正文未提交时继续待处理；非标题图注不会被自动归结构。显式错误、重复、重叠或不成立的标题片段仍被原校验拒绝。
- 只有 Map/request 明确为前置材料时，表格才整体作为 FRONT_MATTER 上下文保留；一般业务表不自动分组。
- 先核对完整 Map/request 的来源、内容和角色，不能通过伪造 is_title 或删正文后重算 request hash 隐藏内容。
- 分批新增时，由程序读取同源同 Map 基线的 covered_scope_ids，自动跳过已覆盖结构；模型不能自行声明“已覆盖”。显式重提旧 scope 仍走既有拒绝/修订规则。
- 绑定回执保存在 `inputs/task-api/*.structure-binding.json`，记录实际来源与自动补齐范围；丢响应后重放同请求读取同一回执。所有内容判断和表格选区仍经原 binder/compiler。

新字段显式启用，旧调用行为保持；旧任务固定包不支持它时明确拒绝，不能静默换包。主skill、source-items角色skill、scope模板、MCP与task_describe已同步指引。
