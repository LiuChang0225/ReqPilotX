## 3. 任务卡

### `AI-01` Azure OpenAI screening 联通

- 建议 Owner：AI/Backend
- 当前状态：`BLOCKED_BY_ENV`
- 目标：
  - 让 `INFO / REQUIREMENT` screening 从 heuristic 切到真实 Azure OpenAI
- 涉及模块：
  - `prototype/app/services/ai_copilot.py`
- 输入：
  - 可用 Azure OpenAI 资源
  - 公司网络或可访问公司 Azure 的凭据环境
  - `REQPILOT_AZURE_AUTH_MODE`
  - `AZURE_OPENAI_ENDPOINT`
  - `AZURE_OPENAI_CHAT_DEPLOYMENT`
  - `AZURE_OPENAI_API_VERSION`
- 输出：
  - `llm_primary` 或 `llm_shadow` 下 screening 成功落库
  - `assessment_runs` 出现 `screening_llm_*`
- 依赖：
  - Azure RBAC 或 API key 可用
- 验收标准：
  - 至少 10 条真实样本成功跑完 screening
  - `INFO / REQUIREMENT` 结果可在 workspace 正常展示
  - LLM 失败时仍可回退到 heuristic screening

### `AI-02` Azure AI Search index upsert 联通

- 建议 Owner：AI/Backend
- 当前状态：`BLOCKED_BY_ENV`
- 目标：
  - 让 knowledge chunks 能真实写入 Azure AI Search
- 涉及模块：
  - `prototype/app/services/ai_copilot.py`
- 输入：
  - 可用 Azure AI Search 资源
  - 知识库样本 2 到 3 份
  - `AZURE_AI_SEARCH_ENDPOINT`
  - `AZURE_AI_SEARCH_INDEX_NAME`
- 输出：
  - knowledge docs 上传后能成功执行 `index upsert`
  - 本地 payload 与云端索引一致
- 依赖：
  - `AI-01` 不强依赖，但通常同一 Azure 环境一起验证
- 验收标准：
  - 至少 1 份 paragraph chunk、1 份 table-slice chunk 成功入索引
  - RBAC 模式能走 `azure_sdk`
  - API key 模式能走 `azure_haystack`

### `AI-03` Azure retrieval + `llm_shadow`

- 建议 Owner：AI/Backend
- 当前状态：`READY_AFTER_AI_01_02`
- 目标：
  - 用真实 Azure retrieval 替换本地 heuristic retrieval
  - 跑通 `llm_shadow`
- 涉及模块：
  - `prototype/app/services/ai_copilot.py`
  - `prototype/app/main.py`
- 输入：
  - 已入索引的 knowledge docs
  - 真实 requirement 样本
- 输出：
  - `assessment_runs` 同时出现 heuristic 与 llm shadow 记录
  - `workspace` 能展示 AI 结果但默认仍可保留旧路径作为回退
- 依赖：
  - `AI-01`
  - `AI-02`
- 验收标准：
  - retrieval 返回 evidence 非空且 source 可追溯
  - `llm_shadow` 失败不阻断 heuristic fallback
  - 至少 5 类样本成功跑通

### `AI-05` Rule Engine 硬约束收口

- 建议 Owner：AI/Backend
- 当前状态：`IN_PROGRESS`
- 目标：
  - 减少 LLM 自由发挥，把硬边界留在规则层
- 涉及模块：
  - `prototype/app/services/ai_copilot.py`
  - `prototype/app/services/assessor.py`
- 输入：
  - 业务规则清单
  - 典型法规 / 禁配 / 冲突证据样本
- 输出：
  - 规则优先级高于 LLM
  - fallback 与 override 路径可审计
- 依赖：
  - 无
- 验收标准：
  - 无证据时不可输出正负结论

- 当前进度：
  - 已完成第一轮本地 hard rules：
    - 冲突证据默认回退
    - 无负向证据不得直接 `REJECT`
    - 法规类缺少 compliance signal 时不得正向判定
    - 强负向证据可覆盖错误正向结论
