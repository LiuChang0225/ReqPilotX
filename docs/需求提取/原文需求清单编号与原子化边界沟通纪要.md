# 原文、编号与派生：产品访谈结论

访谈日期：2026-08-28；公开摘要整理：2026-09-20。原逐字纪要夹带真实案例结构和目标答案，完整原稿在私有资料中保留。本页提炼可分享的产品意图，不把摘要冒充逐字引言。

后续产品定义以[模型 V1](文档结构与原文条目模型V1.md)和[分类 V1](分类与验证关联规则V1.md)为准；本纪要不宣称相应能力全部实现。

1. 下一阶段应继承持久化的 Document Map 与来源上下文，不从空白背景重新猜测文档。
2. DVP、BOM 等按完整工程事项确定范围，保留原表头、组成、条件和来源；不能用物理行数决定需求数量。
3. 原文条目与派生要求分别保存。原文编号来自客户，SRC/REQ 是稳定业务标识，派生 Snn 不改写原文父项。
4. 分类判断需要公开可核对的专业依据，不以关键词、是否含数值或是否出现“应”决定需求属性。
5. 结构、原文条目与派生在同一有序台账中呈现；1:1 共用一行，1:N 才展开，纯标题不重复造条目。
6. 派生是明确授权范围内的工程操作，须保留完整父项与双向来源追溯；完整草稿的自主修订不等于正式接受。
7. 反馈、版本和导出消费同一业务结果；分析判断不能隐藏地改写客户原文。
8. Agent 选择阅读和语义方法，程序承担身份、持久化、校验和确定性机械操作，避免重复会话与重发全文的负担。

这些结论继续指导当前实现。历史条款数量、私人运行路径和参考答案不随源码提供，取用见[资料边界](../源码与私有资料边界.md)。
