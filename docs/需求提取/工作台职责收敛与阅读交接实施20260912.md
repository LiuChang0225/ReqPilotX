## 前端组成

- `DocumentWorkSurface`及测试：阶段展示约束、阅读交接intent消费；`ExternalAgentPanel`接收打开整文草稿的明确请求。
- `SourceItemLens`、`SourceItemReasoningDetail`、`NativeStructureReferenceDock`：按整理／分析职责配置动作；共同选择及Snn恢复。
- `RequirementTreePanel`、`SourceItemWorkspace`、`PluginWorkbench`：带对象的职责切换回调。
- `KnowledgeInspector`、`ForceGraphCanvas`及测试：三态参考案例与真实词条路径。
- `readingHandoff`、`ReadingHandoffAction`、阅读页面及测试：验证已有work、准备草稿、一次性标签页intent和显式打开。正文保留完整发现及来源记录，详细记录可展开查看。
- `App`、`WorkspacePage`、阅读embedded模式、`workbench.css`：共同应用外壳，避免重复品牌／项目导航和嵌套main；阅读区按剩余工作面适应宽度。
- `SourceItemAgentLoop`、`SourceDocumentActions`：新任务自主执行默认值和目标文案。

## 验证

最终聚焦回归 **279项／28文件通过**，TypeScript及生产构建通过，限定路径`git diff --check`通过。包含阶段导航、整理／响应动作边界、派生行、阅读会话、草稿来源与版本隔离、知识案例、路径无解、旧确认任务与新任务可选确认等检查。此前82／56／70／21项为不同阶段的子集，不叠加成总数。

实际页面在隔离18080环境验证：

1. 保护合成v3中，提取选REQ-0008-S01先显示完整父条款及派生依据，没有分析或人工编辑入口；“评审此项响应”进入同Snn的响应视图，“修改父条款”返回同项。刷新后同版Snn选择恢复。
2. 知识库EMC节点实际显示两个参考案例，分别为待澄清与有偏离；不再把4500 A/m案例的CLARIFY显示为技术偏离，完整案例内容保留。
3. 在业务任务提供的独立A1合成任务上，用当前阅读context的真实source_node_id和offset，通过阅读API创建一条明确标为UI验证的临时笔记。随后通过真实页面“笔记→带到工作台草稿→打开已准备草稿”，回到原A1任务、v2、list，协作区自动打开且范围为整个文档。草稿含note ID/revision、原件SHA、capture及定位，仍未发送。
4. 临时草稿用键盘清空并确认空值；测试笔记通过其精确ID和revision删除。A1仍为原v2、2个版本、0反馈；保护旧会话仍为v3、3版本、1反馈。没有提交模型任务、结构确认、需求修改或工程师意见。
5. 阅读进入共同外壳后，实际DOM确认只有一个workspace shell，侧栏可见；返回当前工作保持A1的session、revision和list。1025×675下，工作面宽953px，原文约495px、问答约458px，输入区底部为675px，页面无横向溢出。1440×900也保持单一外壳和无页面溢出。

本轮没有改造后端或启停API／worker。业务任务已自行重载新的接口；本轮并未把多任务sessions接口的存在写成UI已经接入。
