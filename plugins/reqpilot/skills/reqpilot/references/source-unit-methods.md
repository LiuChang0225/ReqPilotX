# Source-unit methods: runnable inputs, correction and readback

Use this when grouping milestones, parameters, mixed BOMs or multi-part tests, or when definitions and supporting figures affect a clause. Generate only the relevant example when current source evidence leaves a real uncertainty.

In a native host call `reqpilot_run` with `operation="worked-example"`, `arguments={"example":"source-units","output_dir":"examples/source-units"}`. In a built bundle use `python scripts/reqpilot.py worked-example --example source-units --output-dir <new-private-directory>`. Source-checkout development adds `--project-root <repo>`. Read `public-calls.json` for the exact public requests and saved results, and `example-receipt.json` for actual task/artifact locations. The source PDF and intermediate decisions are inspectable alongside them.

The generator supplies explicit teaching answers, makes zero model calls and does not establish extraction quality. Its source locations and identities come from a fresh capture and the shared compilers. Counts and keys belong only to this invented fixture.

| Source family | Complete unit in the example | Evidence that changes the decision |
|---|---|---|
| Numbering, pure heading and parent body | The heading is structure. A parent voltage/temperature condition remains readable context; opening and closing targets retain separate source identities and link to that condition | A parent independently imposes an additional obligation: preserve it as such. BOM ordinals or test steps describe internal composition; they do not automatically create more requirements |
| Milestones and parameters | Drawings due at concept approval and samples due at design approval are independent PROJECT items. Idle current and startup time are separate complete QUALITY properties, including condition and unit | One sample package with several named contents and one acceptance event may be one milestone. Several operating points of one target may stay one parameter set. Preserve the table's organization without merging independent acceptance events |
| Mixed BOM and independent obligation | The composition lead and housing/seal rows form one CONSTRAINT item with exact text/table ownership. The separately headed connector obligation remains its own item | Two explicitly independent variant supply lists may be separate BOM units. Component names, row numbers and the word “delivered” alone do not establish independent milestones |
| Complete test and different test | Vibration setup/exposure and the next-page crack criterion form one complete test; the distinct thermal cycle remains separate | Two separately specified complete test IDs provide a boundary. Method, duration, sample count and post-check are parts of a test, even when independently measurable |
| Definitions, conditions, exceptions and verification target | The response target links to its original definition and variant-A applicability, including the exclusion of B. The measuring clause links to that actual target | A condition explicitly limited to another variant must stay outside this target. Identical terminology is only a search clue. Verify the governing source before writing `context_source_ids` |
| Supporting figure, independent drawing and scanned table | Figure 1 remains Map-owned by its textual housing requirement; preserving it creates no duplicate IMAGE SRC | A genuinely independent normative drawing uses the image-item route. A scanned table retains its table meaning: use the original page, bounded OCR/transcription and the visual-source/table tools before authoring table records. This example does not claim a scanned-table extraction run |

The initial BOM classification deliberately contains a known teaching error (PROJECT). The public `revise` request corrects it to CONSTRAINT while retaining exact source text, table cells, source IDs and unrelated items. This is an explicit demonstration of local correction, not a model mistake or a source-only benchmark. The following annotation requests save actual context links. A final `review` with `analysis_policy="preserve"` demonstrates the correct-result/no-change branch without creating a revision. Delivery uses the current registered review and ordinary program Excel export.

For your document, read the real source, select the supported business boundary, then use the current scope template. Rebind every source range and inspect the saved item plus associated context. After a correction, compare affected and unaffected identities and the exact current delivery. When no source-supported correction is needed, retain the version and its existing registered export.
