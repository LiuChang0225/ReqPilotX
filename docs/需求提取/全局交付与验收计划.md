## 共同的图与数据合同

原文件/来源角色 → Document Map文档单元与真实章节 → 原文SourceItem → 需求子集REQ → 显式decomposition Snn → 证据/适用关系 → 工程师响应 → 版本化Matrix。

图工程在此是节点身份、拥有关系、引用、验证上下文、派生和版本关系可追踪，并能约束各Agent并发协作。Document Map父子表示源结构；引用不改变父级；表格是来源内容；技术容器不成为章节；decomposition另有关系。不要增加一套图数据库作为前置。

分类保持有限集合：产品/系统功能、质量、约束，另有项目和过程。法规/试验/包装/标准为主题；非需求保留内容角色；规范性、适用性与就绪状态独立。已接受来源不得被新parser/outline覆盖。没有证据不自动符合。

## 已观察的实际变化

- 旧SourceItem枚举只支持F/Q/C，现已加入PROJECT/PROCESS，未修改旧artifact序列化字段；历史基线与bridge39项测试通过。
- 成熟SourceItem ledger已抽成纯模块供应用/插件复用，避免复刻B1的第二套来源模型。
- 新文件以当前Map和EMPTY源台账起步，首次追加/生长有明确回归；旧同PDF台账只有在Map身份一致时才能作为seed，不能盖过新的Map。
- 新合成文件的生产Map、文本/表格SourceItem、带真实内部资料的分析均已执行；这些运行证明传输/持久化连通，不等于试验粒度与全文语义正确。
- 新增原图SourceItem：图像绑定与Agent释读分开；SRC/REQ退休号不转给新对象。独立审计发现的高水位与注解seal问题已加入回归。
- Decomposition重读会复验子项内容/来源范围，防止重签篡改；原文的备选“或”不能无提示变成AND，“1h以上”不能改成“>1h”。这些机械反例不是普遍语义正确证明。
- 工作台沿用原NativeDock与SourceItemLens；真实浏览器下载使用同一source/版本。发现原窗口锁屏后使用隔离无头浏览器验证，未要求用户解除锁屏。
- 算法优化保留六份SourceIR（除created_at）等价；PEF矢量文字和QC/T隐藏OCR缺口未被伪装解决。
- 全局验收不能只看schema、条目数、搜索命中或单张截图。B1/B1.1的源序/层级/表格失败作为反例保留。
