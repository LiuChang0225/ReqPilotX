# Reference 经验覆盖与压缩说明

本轮依据用户反馈“reference过于单薄，但也不宜冗长”重编。目标是让Agent先掌握正常路径，在证据出现变化时选择相应处理方式。此次修改是技能与reference，不改客户来源、已保存Matrix或业务编译器。

本文记录r15参考整理。后续[r16首轮方法重验](历史方法重验与读取闭环首轮.md)已经接通逐页阅读、局部回查和原生示例入口，并同步实际操作指引；r15发布时的长度/文件统计仍只描述当时版本。

## 组织与使用

- [共用契约](../../plugins/reqpilot/skills/reqpilot/references/business-contract.md)只保留权威、对象、编号、证据、阶段与交付不变量。
- [常规路径与索引](../../plugins/reqpilot/skills/reqpilot/references/reading-guide.md)先给8类普通情形，再按实际疑点路由。
- [表格与关系](../../plugins/reqpilot/skills/reqpilot/references/tables-and-relations.md)、[来源读取](../../plugins/reqpilot/skills/reqpilot/references/source-reading.md)、[判断与响应](../../plugins/reqpilot/skills/reqpilot/references/judgment-cases.md)合计31条处理条目。每条给正常处理、改变处理的证据或反例；这些不是31份已验收客户案例。
- [完整示例](../../plugins/reqpilot/skills/reqpilot/references/worked-examples.md)保留实际可运行的两页合成文档及期望输出，具体字段查看生成文件，删除重复规则和占位JSON。
- [自查](../../plugins/reqpilot/skills/reqpilot/references/semantic-self-check.md)收敛为5个核对面，不重复整份规则。
- [工具索引](../../plugins/reqpilot/skills/reqpilot/references/tools.md)按捕获、Map、条目、图片、拆分、分析/导出、宿主、Office和前文整体分文件。旧索引锚点仍有效；技能直接指向所需主题。原生工具一次返回整份Markdown，分文件才能实际减少无关读取。

正常路径不是只看首页：仍需全文结构盘点、来源覆盖及疑点回源。但普通原生PDF不默认整本OCR，普通条目也不因为存在复杂反例就增加人为拆分或审批。

## 不直接复制的旧口径

1. **“合并范围永远压过文字”**：TAB-002保留为当时特定来源范围的确认结论；不能推广成所有文档的普遍规则。新reference要求结合可见合并、文字适用条件和例外裁定。已绑定来源的有效用户判断不因另一例不同而擅自撤销。
2. **“BOM/产品信息/排期都不是需求”**：保留当时描述性实例，新增规范性供货、配置和交付的相反情况；按实际义务判断。
3. **“所有有意义图片都必须有独立SRC”**：这与内嵌图和本轮封面/目录整体规则冲突，已纠正核验技能为“每幅有意义图片有可验证归属/处置”；独立图才需要独立条目。
4. **“旧父项计数/五个子内容是固定输出”**：当前采用正文编号默认最低层与完整单元例外。历史数量不进入新文档目标，也不把原文子项统一变成Snn。
5. **“图纸一律不读”或“保存图纸就等于读懂所有尺寸”**：前者是旧开发范围，后者没有证据；新reference允许按当前授权与工具读取，准确披露未支持的深度图纸派生。
6. **“只有应/shall才是需求”与“无KB继续逐条填待证据”**：分别用规范语境判断、以及未执行和实际分析缺证据的区别替代。
7. 旧执行顺序、人工逐页approval门槛和某次capture/Gold状态不进入常驻reference；当前用户要求、产品模型和实际能力拥有当前权威。

## 长度控制

按空白分隔英文词衡量，不冒称模型token或实际运行成本：

- 主技能＋共用契约＋起始reference：从约2897词降至约1532词，减少约47%。
- 语义reference＋五个技能合计约5679→5235词；覆盖面增加，通过删除重复规则与按需路由降低常驻负担。
- 专项语义手册每份约700–800词；一个情况只读相关手册，不把31条逐项审查变成任务门禁。
- 原有325行工具大全改为短索引和9份独立主题；技术正文保留，语义选择与字段语法不再混放。

精确统计与校验保存在私有 `prototype/runtime-data/reference-expansion-20260909/`。后续新增条目须有真实观察或明确产品要求，优先补充现有条目的“改变判断条件”；只有出现新的判断维度才新增条目，重复或过时规则应替换。

## 验证范围

2026-09-10补充：[经验迁移审计](历史经验迁移审计与收敛方案.md)已发现当前reference虽覆盖语义判断，却没有完整落地所需读取/示例/恢复能力。新增探针确认示例脚本、表格HTML与compile-annotations的原生入口差异；后续新增经验必须同时指明触发信号、可用动作、产物、反例/恢复和验证。旧人工逐页approval不恢复，但Agent实际逐页视觉复现要求不能与人工门禁混为一谈后一起丢失。不要仅以reference数量或长度评价迁移质量。

r15发布时回看历史经验并进行静态语义交叉审阅，检查链接/锚点、技能格式、包文件和示例工具链；当时未运行新的独立模型盲测。随后[Luna两轮实测](Luna-max-r15实测.md)结构阶段未通过，没有重跑旧客户Matrix。覆盖更多情形和缩短说明不等于准确率提高；方法必须在当前入口被实际使用并按原文验证。
