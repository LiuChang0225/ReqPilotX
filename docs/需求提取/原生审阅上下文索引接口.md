# 原生 SourceItem 审阅上下文索引

该接口为现有来源账本的只读投影，供全文检索、建议重点分析、变更、图片、派生和反馈提示使用。原树继续负责层级与顺序；`records`只按稳定`source_item_id`索引，不构造另一份账本。

## GET

`/api/projects/{project_id}/sor-documents/{document_id}/agent-structure/delivery/review-context`

可带`expected_baseline_sha256`。与当前版本不符返回409；读取过程中发现baseline变化也返回409。响应包含source、Map、baseline SHA/revision，所有字段基于同一个当前版本。

```typescript
type FocusArea = "TECHNICAL_PARAMETERS" | "VERIFICATION";
type ReviewRecord = {
  source_item_id: string;
  source_display_id: string;
  requirement_display_id: string | null;
  search_text: string;
  topics: string[];
  focus_areas: FocusArea[];
  context_focus_areas: FocusArea[];
  focus_reason: string;
  focus_status: "EXPLICIT" | "EXPLICIT_NONE" | "EXISTING_TOPIC" | "UNAVAILABLE";
  needs_attention: boolean;
  attention_reasons: string[];
  changed_from_previous: boolean | null;
  change_summary: string;
  previous_judgment: {
    requirementness: string;
    requirement_kinds: string[];
    non_requirement_role: string | null;
    decision_summary: string;
  } | null;
  rationale_changed: boolean | null;
  derived_count: number;
  has_visual_interpretation: boolean;
  feedback_count: number;
  pending_feedback_count: number;
};
```

顶层另含`records: Record<string, ReviewRecord>`、`history_status: AVAILABLE | UNKNOWN`、`focus_annotation_status: BOUND | PARTIAL | UNAVAILABLE`、`focus_annotation_sha256`、`focus_annotation_revision`、`focus_annotation_provenance`、`focus_notice`及`review_context_sha256`。

- `search_text`取自当前SRC的原文绑定、原表业务行、已绑定表头/共用值、明确共享原文、同源图片释读和实际派生；不会只索引标题，也不会把整段通用上级背景复制给每个条目。原文未改写。退休REQ可作为前版身份检索。
- 重点是独立的**建议重点分析**。显式注释优先；缺标记时仅在已有可靠验证主题及适当产品类别支持下保守提供验证建议，不从数字、标准编号或标题关键词制造技术参数标签。过程审批、报价/交付时点不因此变成产品参数。
- 非需求只能有`context_focus_areas`，其`focus_areas`为空，不冒充待分析需求。`EXPLICIT_NONE`表示本轮已明确不标重点，不能再被通用主题回退覆盖。
- `needs_attention`来自来源绑定的未解决问题、实际图像释读未决、既有证据冲突/不足及待处理反馈。没有内部知识库或未启动分析，不会使所有项成为问题。
- `changed_from_previous`比较实际前版的A/B/F、来源绑定、标签、形式和位置；解释文案的变化单列`rationale_changed`。没有前版时为null/UNKNOWN，不能解释为“未变”。历史工件与当前来源/Map或前驱pin不符时拒绝混读。
- 反馈计数读取实际原生反馈日志并校验project/doc/source/Map/baseline/SRC。`PENDING_AGENT`及`ACKNOWLEDGED`计为pending，`CONSUMED`不计pending；它们均不等于人工接受。

## 独立的受控注释

`review-annotations-put`保存`source-item-review-annotation-decisions/v1`输入，不修改SourceItem或基线。每项包含来源证据SHA、显式重点/上下文重点、简短依据及OPEN/RESOLVED问题。输入必须绑定当前source/Map/baseline；未知SRC、变更的原文绑定、将非需求设为待分析重点或额外分类字段均被拒绝。

```bash
prototype/.venv/bin/python prototype/scripts/agent_workflow.py review-annotations-put \
  --project-id PROJECT --document-id DOCUMENT --input '<private-decisions.json>'
prototype/.venv/bin/python prototype/scripts/agent_workflow.py review-context \
  --project-id PROJECT --document-id DOCUMENT --expected-baseline-sha256 SHA
```

版本以内容寻址工件存储在现有ObjectStore的`runtime/source-item-review-context/`命名空间，保留provenance和前驱SHA；head只提供当前版本位置。更新需给实际`--expected-head-sha256`，采用乐观前版检查，重复同一输入幂等。当前写入仅为本地宿主工具，不开放用户HTTP写入口；没有启动模型或worker。PDS的显式决定留在私有运行目录，通用实现不含PDS关键词分类器。

## 反馈处理能力

响应`capabilities`分别声明支持及当前运行时是否可用：

- `text_scope_revision`：现有`POST .../requirement-baseline/revisions/start`，`affected_scope_ids`仅接受`text:node_id`，可包含边界与判定修订。
- `table_classification_review`：现有`POST .../requirement-baseline/classification/review`，body为`command_id`、`expected_source_sha256`、`expected_baseline_sha256`、`source_item_ids`、`feedback`，新增可选`feedback_ids`。只复核A/B/F，保留原表行组，不能承诺表格拆合。
- `table_scope_revision`：当前不支持。表格边界问题可保存反馈，不生成一个不能执行的“表格范围修订”按钮。

分类重评选择的feedback IDs必须绑定同一项目/文档/版本/条目；成功后所选反馈携带为CONSUMED，其他未处理反馈携带为ACKNOWLEDGED并继续计pending。失败不伪造完成。此轮只实现/校验能力与读投影，没有实际启动分类或分析。

## 本轮实证

### 同源修订后的派生与分析继承（2026-09-08）

共享 `rebind_source_item_decomposition` 与 `rebind_source_item_assessments` 在基线变化后核验实质输入：来源、Map、父项身份/分类/上下文、原图释读及内部知识。只改变版本包装或解释文案时可保留未受影响成果；已改变的父项/分析对象明确返回 stale IDs，不能冒充新模型重评。原历史、Snn 号码注册表和退役号保留；知识目录变化时旧分析待重评。继承本身不产生人工接受。该合同由插件与应用共用，独立于审阅重点标记。

跨Map继承须有[共享Map修订回执](DocumentMap同源修订接口.md)：纯节点/表scope身份重绑保留未变化成果，实际上下文变化强制待重评。原编号、主题及其展示注解证明的补齐不使旧分析全部失效；原图释读文字、图片绑定、真实来源/类别/条件或内部知识改变仍需重新判断。

原文范围形式修正保留已有USER_OVERRIDE/REVIEWED的完整判断；自动流程不会改变或通过拆分移除人工覆盖判断。已有Agent判断实际变化时恢复UNREVIEWED，不把新Agent措辞标成人工接受。边界撤销只撤销该原文范围操作，历史派生/评估保持历史，复用须经过当前来源和输入的显式校验。
