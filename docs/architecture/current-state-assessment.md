# ReqPilotX 当前架构评估

更新：2026-09-03。

现有模块化应用、PostgreSQL/对象存储、核对工作台与 Agent 适配有复用价值，基线清理没有重写它们。
但“组件可用”“F06 两章局部结构可见”与“新文档完整目标态”不能混为一谈。

## 当前判断

- 当前优先验证真实产品结果，不先证明某一框架是唯一选择。
- 最大缺口仍是新文档完整理解、原文条目/分类/派生拆分与可核对纠错，而不是再造一套运行平台。
- Codex 原生与 App Server 没有必须分叉的业务逻辑；应共享能力核心，显式处理上下文、工具和宿主差异。
- 会话、检查点和任务状态要保留全局发现及已接受范围；不能只传摘要或静态答案。
- 保留确定性来源、身份、覆盖、版本与安全校验，不让这些工具替 Agent 决定语义全集。
- 原表渲染、PDF 联动、用户反馈与版本安全是产品能力，不因框架自由而降为无来源演示。
- 既有数据不得为架构整理而重新初始化；当前 PostgreSQL 与对象存储仍是现有应用的数据真相。
- 跨宿主可安装、单次案例成功、自动测试通过、产品验收与生产发布分别验证。
