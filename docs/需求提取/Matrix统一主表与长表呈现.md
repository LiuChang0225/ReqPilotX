## 找回的定义与本轮修正

仓库历史提交 `2fbe50e` 的 `DESIGN.md` 已定义：一张完整有序、包含业务层级和派生关系的 `ComplianceMatrix`，每个逻辑原表独立工作表，冻结数据放隐藏元数据表。此前把“不重复上下文”理解为分开响应表和原文索引，偏离了这一点。

当前恢复以下行为：

- 主表包括全部原文标题、正文、非需求内容、表格节点、原始需求及显式派生项；按冻结树顺序排列，保留缩进与可折叠层级，默认展开。
- 共享信息已有完整 SRC 绑定时，直接引用该行；其他共享原文在真实所属位置展示一次。章节占位文字不会被打印成客户标题。
- 判断只维护一套。原表工作表完整还原单元格、合并、跨页与图片；右侧导航列可返回相应主表 SRC/REQ，导航不进入原表打印范围。
- 父项汇总已判断、待判断、不符合与偏离数量，不用多数结果推导“整体符合”。有派生子项时保留完整原文父项，但分析分母不重复计数。

用户随后指出“表格、需求、文控信息”被导出混在同一列。原因是导出层把结构类型、需求判定和非需求内容角色合并为一个显示值；这是错误映射，提取阶段的定义没有改变。现修正为：

| 维度 | 导出呈现 | 来源 |
|---|---|---|
| 原文结构 | 独立结构类型、原编号、标题、缩进与折叠层级 | Document Map / 节点关系 |
| 内容判定 | 需求、非需求；纯结构行留空 | `requirementness` |
| 内容角色 | 文控信息、修订记录、参考、背景等 | `non_requirement_role` |
| 需求类别 | 功能、质量、约束、项目、过程 | `classification_paths` |
| 主题 | 试验验证、法规、物流包装等 | `topic_tags` |

表格不会因其结构形式被判为需求或非需求；派生关系继续由 Snn 身份和父子关系表达，不成为第三种内容判定。导出不自行重判原文。

## 结构规范与使用者视角的补充

用户认可整体格式后，要求补回原有的结构标识、大节点信息，并在原表sheet内安排详细分析。独立“结构类型”列现表达文档、章节、条目、内容、表格、表格条目/分支、图片与派生条目。它复用当前图中的对象信息，不新增章节，不用编号深度猜测业务类别。一个文档根可以同时承载一张表，仍显示文档类型，并在范围摘要中注明原表数量。

大节点显示本范围原文条目数、需求/非需求数、逻辑原表数、派生数（存在时）与当前评审进度；只汇总已有事实，不生成看似原文的摘要。工作簿页头明确显示原文基线版本。

工作簿页头、逐项判断和父项汇总共用同一分析集合：可见、需要分析且具备分析资格的节点。原文与结构共用一行时，展示节点ID可以不同于SRC身份；不能通过这两个ID是否相等重新推断派生父项是否进入分母。完整父项仍显示，其已被派生替代的分析任务不重复计数。

参考依据：

- [Polarion Document Parts](https://developer.siemens.com/polarion/advanced-concepts.html#document-parts)区分heading、workitem、table及普通文档内容；Heading在其实现中可以关联Work Item，不能据此将客户章节当成需求。
- [Windchill RV&S 文档结构](https://support.ptc.com/help/windchillrvs/r13.0.0.0/en/IntegrityHelp/client_docs_what_is_a_document.mif-2.html)区分Document、Section和Content/Node；Category由管理员配置，不是一张必须照抄的通用需求分类表。[结构与追踪关系](https://support.ptc.com/help/windchillrvs/r12.3.1.0/en/IntegrityHelp/client_docs_what_is_a_document.mif-3.html)也有不同用途。

借鉴的是结构、业务对象、引用/派生关系分开建模的做法；ReqPilotX继续沿用已确认的A/B/F与有限需求分类，不照搬供应商产品枚举。

| `T010_主动前减振器试验大纲` | 左侧完整设备/方法、条件、要求、责任、样件、周期、备注及原图；右侧逐项分析 | 读原表时同时核对判定和分析，必要时返回主表修改 |

这 63 项来自完整原文试验记录的 SourceItem 划分；导出没有把它们重新派生为 Snn。只有进一步明确拆分一个完整原文要求时才产生 Snn。BOM、测试项目矩阵等是否整体保留，仍由原文条目与粒度决策决定，导出器不自行按物理行制造需求。

每张原表顶部可点击“查看本表逐项分析”，直接跳到右侧同表分析区。分析区包含整体概况，以及原文条目、内容判定、角色、类别、主题、需求提取判定依据、响应判断、响应分析/证据/缺口。分类与响应判断公式引用主表并带缓存值；同一版本只有一套结果。现有派生项的响应逐项列在原文父项的分析说明中，保留返回主表的入口。尚无内部证据或未运行分析时不填写符合结论；失效结果明确要求重新分析。

同表并排会增加横向宽度，因此提供直接跳转并冻结表头。分析区供Excel阅读，默认原表打印范围只包括原表；需要打印分析时由主Matrix承担，避免重复打印。

后继版本中的`source_item.visual_interpretation`现可被导出消费。表格来源项在同表分析区显示独立“Agent图片释读（以原图为准）”列；非表格来源项在主表说明区另行标注。客户原文、原图、SRC/REQ与内容判定不被释读替换；待复核、未决信息与长文本全文批注保留。来源、条目、版本或图像绑定失配时提示未展示释读，仍保留可信原文。旧v26快照没有的释读不会被导出器补造。该增量70项聚焦检查通过；真实v27 HTTP导出也已逐项核对34条释读、36图锚点与36张嵌入原图，714个内部链接有效，449 SRC与58派生按实际树序保留。SRC-0080原表/独立释读列另做渲染抽查。验证范围为导出绑定、内容位置及显示，不冒称全部图片数值的独立语义接受。
