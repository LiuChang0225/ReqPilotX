## 目录与责任

```text
<working-root>/runtime-data/projects/<project-key>/
  project-index.json
  documents/<document-key>/
    document.json
    tasks/<work-id>/
      TASK.md
      task-context.json
      workspace-index.json
      source/<original>
      reading/<operation-id>/
      inputs/<operation-id>/
      outputs/<operation-id>/
      operations/<operation-id>.json
      host-receipts/
      notes/
      review/                         # 按需使用既有review owner
      runtime-data/workbench-bindings/
```

- 一个文档可有多个独立任务；同一SHA、同名文件都不能自行认定为同一委托。显式复用document-key时验证原件SHA。应用project/document身份与本地key分别保存。
- 原件复制后校验，Agent阅读衍生资料，不改原件。工具与skill由环境提供，不在每个文档目录复制一份。
- TASK是程序生成的接续入口：实际委托、来源、当前成果与剩余范围、确认要求、可用路径及运行来源。自由调查笔记放notes；不能靠修改TASK宣称已提交或人工接受。
- outputs保持每次编制的完整bundle。Map的source、SourceIR、decisions、scope requests和表格证据不能只剩一个JSON。review和原生阶段快照属于各自owner；“能展示”不自动等于“能重编”。
- inputs冻结本次编制决策JSON。引用外部依赖时记录路径与摘要，明确标为EXTERNAL_PATH；没有声称所有外部文件已经打包。

## 保存、当前工作版和恢复

小型`artifact_kind_catalog`复用已有模型及验证器；`task_workspace`负责路径、操作与导航索引。Agent仍决定来源含义、边界、分类、图像释读与有依据的分析；程序承担路径、来源/依据填写、编号、编制、校验与保存。

每次操作先登记依据与预期工作版本，调用真实编制器，再校验完整bundle，最后写不可变`operation-receipt.json`并短锁更新索引。目录存在或进程退出零都不足以认定成果成立。

| 结果 | 含义 | 对当前成果和工作台的影响 |
|---|---|---|
| COMMITTED | 完整成果校验通过，依据仍符合当前工作版 | 可以提升选中工件；支持的桥接操作随后同步 |
| SAVED_CANDIDATE | 结果有效，但不属于当前Map或尚未纳入已有review | 保留候选，不替换当前工作版、不自动同步 |
| CANDIDATE_CONFLICT | 编制期间工作依据/代数已变化 | 保留结果供明确择取，不按mtime选赢家 |
| BLOCKED / FAILED | 等待真实确认或编制失败 | 保留操作、诊断和已产生文件；不把半成品标成完成 |

只有source或Map也可以接续，无需先有Items、review或Excel。恢复读取有效提交回执，可找回“回执写好但索引写入中断”的成果；半目录继续列为未完成。

已有review的真实head拥有当前工作版。非当前Map/Items可以读取，但不能因为导出引用它们，就反向提升为当前成果。阅读索引、导出、同步回执与业务owner是不同职责。

工作台同步发生在本地提交之后。实际同步结果另存host-receipts，不重签本地工件；离线、未绑定或冲突不能伪装为前端已收到。需要Map版本确认时，换cwd或使用custom binding都不能绕过确认；尚未绑定时返回明确状态。

自动发布另用本机任务publication锁，取得锁后重新核对实际选中SHA和producer/owner。连续两代即使Map SHA相同，迟到旧操作也不能覆盖已发布的新操作；返回SKIPPED_SUPERSEDED并保留本地成果。不持核心提交锁等网络，也不声称跨机器全局排序。显式workbench仍表示用户选定成果的同步操作。

公共命令为`workspace init`、`workspace status/recover`、`workspace run <operation>`；具体最短例子见[随包指南](../../plugins/reqpilot/skills/reqpilot/references/task-workspaces.md)。支持capture、reading-workspace、compile-map/items/images/annotations/decomposition、deliver和review-open；review-close继续调用原入口。默认结果保留接续必需字段，完整历史用`--full`或读取index，不反复把全历史JSON回传给Agent。`workbench --workspace`补连自动选择真实review、Items或Map；显式source-only仍保持。

## 原生阶段与前端映射

原生物理目录不迁移。`stage-results.json`保持MAP/ITEMS兼容结构，但只投影当前配套；`stage-history.json`与`.stage-artifacts/<stage-version-id>`保存可读历史。

Items先到可以保留；Map登记后仅当匹配候选唯一时配套。Map A→Map B→迟到Items A不能把A提升成B的当前条目。多候选明确UNSELECTED，旧成果可按stage_version_id或artifact_sha256读取。原生简报保留producer_path并区分完整编制目录与只读阶段快照。

| 工件或状态 | 当前消费者 | 后续界面边界 |
|---|---|---|
| 原件及reading页Markdown/高清图 | 现有阅读工具和源定位 | 阅读入口须带共同工作与查看版本，不能丢任务上下文 |
| Map及SourceItems | 既有结构/台账工作面 | 共用原编号、顺序、来源关系与同版内容 |
| 图像释读、拆分及review | 既有review与传输支持的成果 | 单独overlay先保存；纳入完整review后按已有支持范围同步 |
| 本地操作/提交/同步回执 | TASK、workspace status与明确工作台链接 | 不把本地操作记录伪称外部Agent实时运行遥测 |
| 文档内多个plugin session | 新的只读sessions API | UI已接入共同work/viewed-result/selection及source-only恢复，详见[多任务接入](实体任务工作区-UI多任务接入.md) |
| 同版交付 | 现有程序Excel导出与review-close | 不触发模型全文重读，亦不把导出成功等同人工接受 |

`GET .../agent-structure/delivery/plugin-workbench/sessions`只列当前project/document/source的真实session，不自动选择current；空任务保留，坏索引或其它原件版本单独列unavailable。稳定session ID排序仅为可重复展示，不表示成果新旧或优劣。所选版本与反馈继续使用既有详情端点。

[UI根因分析](工作台断链与职责重叠根因分析.md)已由专门UI任务交付。阅读与知识库断链、快捷作业/连续任务、反馈入口和整理/响应职责，需要围绕共同工作上下文实施；新增目录和多任务列表不能独自解决这些问题。前端文件仍由该任务负责。
