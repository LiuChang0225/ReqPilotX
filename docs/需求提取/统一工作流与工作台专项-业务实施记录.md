## 已实现

- 原编号提取沿用原Matrix的确定性规则，抽为`project_source_item_number`，原文/多原号及Snn来源投影进入outline/reader；没有让前端再次推号，也不改变旧Matrix快照。
- 新增共用`source_item_workbench_metadata`：按唯一SRC统计直属/完整子树、需求/非需求、派生和实际分析单元；数据属于已保存范围，不以数量声明全文完整。合成第2章为直属1、子树8 SRC/8原文需求、2派生、9分析单元。
- `source-findings/v1`首轮扫描已保存Map中同级数字正文编号，区分间断、重复、回退。报告绑定来源、Map、节点、两端原号及定位，状态为待回查原件且不阻断继续。目录/前置内容与不同章节号前缀不混比；字母/图表序号与OCR、捕获缺失仍需另行回源，未声称全覆盖。
- `compile-map`、`deliver`分别落地`source-findings.json`；`audit-map`和`review-verify`返回同一范围报告。通用发现处置API尚未实现，当前通过有来源依据的review反馈与局部修订记录核查结论，不在skill中编造resolve命令。
- 新编制decomposition保存KEEP/UNDO/SPLIT理由与父项证据；`review_scope`保存授权/已处理/剩余身份。CLI使用现有authorization范围，部分编制成功与授权范围完成分别返回。相同基线继续时保留理由，来源/分类/上下文变化后重核；旧工件保持原字节，不补造缺失理由。
- 插件公共读状态增加真实goal、producer/work引用、同步时间、UNREPORTED执行状态、按动作声明的capabilities和反馈回执。缺取回凭据仍为UNREPORTED；插件报告修订不等于已送达或人工接受。反馈/确认/导出继续用原API和幂等存储，不新增模型。

## 重要纠正：W09撤回

上一轮将`dict.get(key, default)`误读为tuple索引，并用错误模拟得出“13项编号误报”。直接运行旧已安装版本的`review-verify`确认它没有该误报。已撤回W09、修正私有错误复现和主稿；实际索引语义保留。现新增编号间断检查是在真实原编号投影上增加范围检查，不是修复这个不存在的索引问题。

证据：旧联调目录中的`installed-numbering-verification-correction.json`；新版`review-verify`对同一v3返回一条`2.6 → 2.10`编号间断，没有虚构13条缺号。
