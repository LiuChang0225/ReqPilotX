## 分层测什么

| 层次 | Agent获得的内容 | 评价对象与证据 |
|---|---|---|
| L0 程序/发现预检 | 不运行模型 | 文件与版本、真实技能目录、脚本/依赖、模型/effort、工具schema、来源绑定、失败请求重放。只证明环境和代码合同 |
| L1 入口与范围行为 | 新会话、自然用户任务、宿主正常可见的技能目录与环境信息 | 是否正确选用/拒绝无关skill，是否知道业务用途和当前阶段，是否实际调用正确入口并产生最小可检查工件；不能只让Agent复述规则后判理解 |
| L2 阶段能力微测 | 相关原页/高清图与必要上下文，或有明确来源的冻结Map/条目/候选，以及相同业务目标 | 分类、分组、条件/定义关联、派生和局部自查修订。给定正确Map的测试仅证明Items能力，不证明模型能自行读出Map |
| L3 整文档自主交付 | 只有原件、共享包、任务与必要宿主事实 | 阅读→结构→条目→必要派生→自查→同版工作台/Excel；实际范围完整，无开发者救场。此层保留自由调查与逐步保存，不强制工具顺序 |

L1触发测试不得提前指定正确skill或强制预加载它，再声称路由正确。L2可显式加载被测角色，但成绩必须注明“角色已给定”。阅读工件生成、实际取用、业务正确与界面可见分别计量。

## 首批用例族：正常情况与变化后的反例一起设计

以下是待落实的用例规格，不是已经执行的测试数。短用例也必须给足支配语义的上下文，不能因裁切掉定义/表头/前页而制造模型失败。

| 用例族 | 正常行为 | 必须区分的反例或变化 |
|---|---|---|
| E01 触发与职责 | 自然SOR委托能进入主skill，知道成果用于需求评审/报价/澄清，并接入实际工作台 | 无关任务不启动提取；已有任务不因切换CLI/MCP重复初始化 |
| E02 范围与交互 | 完整任务自主继续，逐步保存；明确无内部依据则跳过符合性判断 | Map-only不生成后续Items/Excel；明确先确认结构才等待；内部依据未知且影响分析时查找/提出必要问题，不虚构合规结论 |
| E03 定义与适用范围 | 跨章定义关联到真正使用它的条目；明确编号范围内的条件正确关联 | 相同术语但不同变型/附件不乱挂；范围外或被例外排除的条目不挂；已保存定义不等于建立有效关系 |
| E04 分类 | 产品验证目标连同方法/条件保持QUALITY；普通功能/约束/交付义务按含义分类 | 独立校准记录/审批义务仍应识别PROCESS，里程碑报告仍是PROJECT；不能为了修过度PROCESS而禁止一切测试相关PROCESS |
| E05 粒度 | 独立编号要求分别识别；完整BOM或一次完整试验保留组成及整体理由 | 普通需求表不能一律整体；两套独立BOM分支可分别成项；真实原编号子项不冒充Snn，Snn也不替换父项 |
| E06 结构与原序 | 封面/目录/文控整体保留，父级正文与有意义无编号正文可读 | 同页有目录和正文时不能整页排除；PDF对象写入序不同于视觉序；跨页续文不能被割裂或编号排序重排 |
| E07 表图关系 | 表内图仍属表，条款附图随条款并另存有依据的释读，跨页表保留表头/脚注/合并关系 | 独立图与辅助图区分；装饰图不自动变成需求；扫描表不因介质为图片就丢表格语义 |
| E08 自查与局部修订 | 对含错候选，凭原件找到问题并只改真实关联范围，保留稳定身份/正确内容 | 同样任务给正确候选时允许检查后不改；不能为表现“自查”制造错误、无意义版本或新义务 |

先落实E03的两个短用例：一个检验遗漏定义关联，一个检验明确适用范围外的多挂。使用不同于旧五页文档的编号/术语/值；后续再加例外、变型和其余用例族。通用reference保留精炼的“正常例子—变化条件—不同判断—理由”，评测用例及答案留在包外，不能把同一答案抄入reference后当泛化通过。

## 如何判断skill本身有没有价值

1. **先固定兼容的当前工具代码，再比较A/B。** A使用54809共享skill/reference，B使用待改skill/reference。相同模型/effort、工具与程序文件、源/阶段fixture、任务、权限和外部依据策略，只允许声明的指令文件变化。
2. 54809相对033408同时改了指令和读取接口，历史整体收益不能归为纯skill效果。若本次又必须改工具，就单独记录为“skill＋工具组合改动”，以程序重放核对，再做整链验证，不硬称单变量A/B。
3. 在Luna Max内部比较A/B，在Pair Qwen High内部比较A/B。**旧Qwen Medium对新Qwen High不是skill对照**。两宿主比较仍是组合观察，不是纯模型排名。
4. 首次只安排上述两个短用例的A/B：2用例×2版本×2目标配置＝8次短任务，先定位方向；失败或波动再针对性重复，不默认铺开全部用例族的全排列。此处是待执行计划，本轮没有启动。
5. 有必要时才做定向消融，例如移去某段方法/某份reference；保留双方都需要的业务定义和合法工具环境。默认不做“把业务规则全拿掉”的无skill基线，避免比较信息不足。
6. 一个版本通过某次运行不能宣称稳定收益。优先看源语义与范围是否正确、是否自主修正，再看无必要介入、可避免往返、token和首件时间；出现不稳定则保留分布/样本数，不只挑最好一次。

当前skill已经写明“候选不自动成为关系”和“术语相同不等于适用”。因此先检查触发/读取/实际决策失败在哪一层，再决定是否补一个编号范围反例、调整指令位置或改读取回包；不以继续加长文档代替验证。

## 评分必须先校准

- 小用例建立源证据支持的正例、已知缺陷候选及可接受替代结果。原序、原文、阈值、身份/版本和指定关系可做确定性检查；语义有合理多解的部分用来源评核，不把内部ID拼写、固定17/12数量或Snn数量当答案。
- 条件关联检查同时包含must-link与must-not-link；来源对象、范围和例外均绑定到原件。关注有效上下文，不用“多挂总比漏挂好”代替判断。
- 用已知错误与正确候选检查评核器：必须能发现漏项/错序/错误关联，也不能再次把owner_unit_id当章节归属、把工程澄清自动判成源提取错误、或为正确候选硬找修订。
- 程序重放、操作者审阅、独立模型审阅、工程师接受分别标记。当前不预设新增付费模型裁判；未来引入时先校准漏报/误报，裁判不能看到生产者隐藏思维、旧答案或本次期望结论。
- 候选与评分不进入生产者工作区；显式植入错误的局部修订属于组件测试，不能冒充“从原件自主发现全部错误”。没有浏览器能力时真实链接/工件交付与浏览器核验分开，不伪造界面成功。

## 工具减负与延迟观测怎样接入

先对Pair已有66轮按公开动作/依赖/输入输出标注：必要串行、合理同版复查、独立可批量读取、格式修正导致重发、可避免重复、证据不足。**60轮单工具不是60轮浪费**，不得以多工具率或少读文件作为成绩。

优先验证已有文件输入/局部修订/短引用/具体schema导航是否可直接复用，再决定是否补代码。可落程序的字段格式、引用/版本、错误定位及合法机械规范化由程序处理；语义分类、编号范围含义和表格分组仍由Agent判断。未知枚举、冲突来源或有歧义输入不静默“纠正”。

下一次必要模型运行记录请求准备、发送、响应头、首个有效delta、流式结束、工具/持久化时间和上下文/输出计数；只存元数据。缺少某宿主事件就注明缺失，不按另一宿主推算。第一份可审查Map/Items/最终Excel的时间与自然完成时间分开。High是质量对照配置，不是已证明的提速措施。

来源提醒补类型化“Agent已回查原件”的记录，仍展示真实编号缺口；不补号、不静默删除提示、不伪装工程师接受。纯编号label的正文预览属于UI适配，跟进既有UI会话，不让模型重复维护展示文本。

## Pair应用插件接入的独立验收

共同[Pair应用插件方案](Pair首个应用插件架构与实施计划.md)已经规划另一条产品接入线。上述skills微测不阻塞它的原生只读面板；UI迁移完成也不是语义微测前置。当前Pair headless运行和5技能安装不代表完整应用插件已验收。

UI/宿主线在既有业务核心上验证：指定工作/会话/原件/结果版本准确绑定；只读查看不调用模型、不把整页内容自动注入聊天；真正提交事件驱动渐进成果；反馈/取消/恢复作用于正确工作；PDF范围读取、图片及Excel下载可用，依赖和进程所有权明确。此线由应用/UI任务负责，不在评测harness里另造聊天、业务状态或导出器。

汇合时，用同一共享候选和业务任务在Pair真实应用入口验收一次，确认这些宿主上下文与工具确实提供给Qwen High。Luna Max保留为共享能力的对照；即使两宿主共用模型目标，也分别报告应用集成与源语义成绩。

## 整链与新原件的完成条件

组件达到预定源语义约束后，冻结共享候选，Luna Max和Pair Qwen High再各做一次完整任务；两者使用同一业务目标/包，允许不同合法工具路径和拆分处置。出现共同能力缺口时修共享层，不给某模型专属补丁，也不让一个模型替另一个修成“自主成功”。

保留五页用例作回归。另从ReqPilotX已授权资料中检查一份未用于当前调参的代表性文档及其资格，优先覆盖混合/扫描/全表格、跨页和表内图等尚缺的证据。用过的资料只能称新验证/历史回归，不能改名held-out；无合格原件时该项继续待准备，不假造完成。

限定初版要说明支持范围、已测样本、语义缺口、恢复能力和实际UI/Excel一致性。微测通过不代替整链；一份真实文档通过也不证明所有PDF/Office或生产SLA。默认自主交付与用户主动反馈修订是两条验收路径，不以生产中逐条人工纠错兜底。
