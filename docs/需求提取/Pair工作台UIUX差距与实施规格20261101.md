# Pair 工作台 UI/UX：差距与实施规格

日期：2026-11-01。审计基线：ReqPilotX `97afead`；实施候选：`codex/reqpilotx-workflow-ux-20261101`。本文件承接用户本轮要求及[统一工作台专项](统一工作流与工作台专项.md)，不新增业务模型或独立实施计划。本文件包含源码审计与实施规格；后续实现已在独立合成预览核对。真实Pair安装、真实模型和客户业务验收仍单独记录，不用源码或fixture冒充通过。

## 1. 目标和设计方向

用户是需要快速核对 SOR 的工程师。主要工作是看清来源层级，阅读已提取原文，在同屏原页框选处验证，再进入识别、分类和证据分析。界面模式为 Operate；沿用现有工程工作台的中性底色和系统字体，并接入用户已经选定的 Green Compass v7，不进行新品牌生成。

桌面采用顶部紧凑工作流、左侧窄层级树、中间醒目的提取原文、右侧原页对照。当前用户要求优先于旧 DESIGN 中在常用窄屏互斥显示文字/PDF 的方案：宽度不足时先收起树和辅助区，优先保留文字与原页并排。依实际容器宽度降级，不能只检测浏览器宽度。

## 用户现场修订 C1–C7（优先于初稿中的双层阶段栏）

- C1：顶部保留唯一主流程；提取内部只有“结构/原文条目/需求”紧凑查看方式，不再有第二套编号进度，AI分析从主流程进入。
- C2/C3：中间提取原文保持主视觉；标题与身份/原编号/路径压紧，正文进入首屏上半部，低频动作在正文之后或更多中。常用单页原文不重复设置整行页码；无文字片段的表格/图片保留必要定位入口。
- C4：采用用户已批准的 Green Compass v7（canonical revision `45a00e136f9f76e5086ddc5a88dffc7439dd522c`），四个SVG原样复用，明暗版本分开显示，不生成新商标。配置、主题等低频按钮进入更多。
- C5/C6：深度来自实际 `parent_row_id`，保持统一的展开/叶项gutter；1:1条目优先展示有来源权威的原文章节名，原文摘要不代替章节标题。采用克制的细竖向guide和排版，不使用硬直角折线，不补造层级。
- C7：宽屏logo/项目在左、主流程位于页面中心、更多在右；较窄时次要上下文合理截断，不与导航重叠。主流程不混入项目数等容易误读为进度的计数。

这些是同一领域成果的展示修订，不改变来源、派生、分类、分析或发布合同。默认列宽20/40/40，既有用户调整仍可恢复；真实拖动必须改变实际宽度。850–900内容区先收树并保留正文/PDF双栏，只有更窄才切换阅读面。

## 3. 视图、字段与信息递增

“递增”指已保存信息与证据增加，既不要求行数递增，也不要求每阶段重新生成另一套记录。四用户视图与现有六个执行阶段分开。

| 视图 | 主表默认字段 | 中栏默认内容 | 按需信息 |
|---|---|---|---|
| 文档结构 | 原编号/层级标题、来源页、可核对状态 | 当前节点自己的完整提取内容；无正文节点显示其下内容范围 | 捕获方法、技术定位、覆盖诊断 |
| 原文条目 | 原编号、提取原文摘要/完整父子层级、来源、SRC | 完整原文、结构化原表和所含图像，保留有意义非需求 | 条目边界理由、引用上下文、处理轨迹 |
| 需求清单 | 原编号、需求内容/真实父子关系、REQ（可查SRC）、类别 | 完整原文或明确标识的派生表达＋直接原文依据；完整父项可见 | 分类理由、主题、适用性；非需求和待保存范围可回原文视图查看 |
| AI 分析 | 原编号/REQ、需求内容、分析状态/建议、证据摘要 | 提取原文仍醒目；结论建议、引用证据和差距单独分组 | 完整证据、适用条件、人工响应历史、修订变化 |

- 所有表格通过语义列名控制宽度，内容列最大；不把每个属性都变为独立列。小标签只在能改变当前操作时保留，来源/身份可通过稳定的小字号副文本表达。
- 类别栏只简化呈现既有分类：系统需求下的功能/质量/约束，以及项目/过程要求。主题标签与类别分组，多个已保存类别仍保留，不通过UI选择一个“主类”或创造新类别。
- `requirementness` 当前只有需求/非需求两值。缺少条目、判定工件或读取失败不是“非需求”，显示“尚未保存/未读取”，不在浏览器伪造 UNKNOWN 业务分类。
- 需求视图是已保存、有源 SRC/REQ 的真实子集；保留祖先路径，不删除原文台账的非需求项。派生行只能来自已有 decomposition，不按句号或换行自动拆需求。
- 原文包含关系与工程派生关系使用不同标识。独立附件按真实文档单元展示；文内附录不自动提升为独立文件。

## 4. 布局和交互合同

```text
ReqPilotX / 项目       项目管理 · 需求提取 · 需求分析 · 矩阵导出       更多
当前工作 / 版本 / 真实保存或执行状态                                  Agent 协作
┌来源层级────────────┬提取原文───────────────────┬原文 PDF───────────┐
│结构 / 条目 / 需求  │紧凑标题 · 编号/身份 · 路径 │当前页与真实框选   │
│正文/附件           │正文/表格为视觉主体          │整页/聚焦/缩放     │
│ └章/子章/条目      │分类、分析按当前视图展开    │                  │
└────────────────────┴───────────────────────────┴──────────────────┘
```

1. 顶部只保留必要上下文、流程、版本和动作，不叠加介绍卡、长状态段和第二套相同导航。仅保留一套顶部主流程；提取阶段内的结构/条目/需求是左侧紧凑查看方式，不再编号或独占整条阶段栏。宽屏主导航相对工作台居中，左侧品牌/项目与右侧更多各自对齐，窄屏避免重叠。
2. 中间原文是主阅读区：正文使用约16px、至少1.6行高，原文与AI解释清楚分组；长文本完整可读，表格自身滚动。技术ID不会成为字号最大元素。正文区域与右侧PDF的起始阅读高度接近。
3. 有足够容器宽度时显示三栏。常用较窄窗口先将树收为抽屉/紧凑入口，让提取正文与PDF继续并排；确实不足以提供两个可读面时才用正文/原页切换。具体阈值须在独立preview中以1104×780和1024×675核验，不能靠固定viewport宽度宣称通过。
4. 点击树或表格项保持同一稳定选择，更新正文、PDF页码与已有框选；跨页条目显式列出页/片段入口。切换视图、语言和宽度保留当前来源、版本、可匹配选择、展开与草稿；新成果不抢焦点。
5. 引用来源不存在、只有粗定位、页面未加载分别表达，不制造bbox或将空列表表示为“精确0框”。父项及派生项必须定位自己的绑定片段。
6. Agent讨论/设置/原始轨迹按需打开；运行阻断和待用户输入仍就近可见。用户不必理解模型配置才能核对内容。

## 5. 进度与编排接缝

现有 `workflow.stages`、`next_stage` 和保存的版本工件是进度权威。`SOURCE_MAP` 映射结构；`ITEMS_CLASSIFICATION` 同时支撑原文条目与需求视图；`EVIDENCE_ANALYSIS` 映射AI分析；`SELF_CHECK`/`DELIVERABLE` 表示自查/交付。不把视图点击当运行步骤，也不制造单独识别百分比。

UI区分“当前查看视图”与“当前执行阶段”。状态可显示未开始、处理中、部分完成、已保存、等待输入、未执行、待更新；只有可信分母才显示比例。无知识依据时保留“分析未执行”，不能表现为分析完成或错误地阻断原文审阅。旧分析因上游修订失效时显示待更新，不隐藏历史依据。

本轮已实现的 `stage_focus` 为 `GUIDANCE_ONLY`，只指导模型的职责、可读范围请求、工具建议、出口证据和下一动作；UI不得用它覆盖正式工件状态或据其推断完成。

## 6. 分块实施与边界

- UI-A：Hosted 顶部流程和单一辅助入口。主要文件 `WorkspaceShell`、`ReqPilotXReadonlyPanel`、共享样式及对应测试；保留独立Web既有导航能力。
- UI-B：原文/需求分视图、阶段字段投影、选中与版本连续性。主要文件 `RequirementTreeStageRail`、`SourceLedgerTable`、`NativeStructureReferenceDock`、路由/host selection 的最小必要类型与对应测试。只改表现模型，不改后端分类或来源数据。
- UI-C：中央提取原文与右侧PDF并排、响应式树、来源联动可读性。复用 `SourceRequirementNodeLens`、`PdfViewerPage` 现有合同，主要改布局、视图配置与信息层级；不得弱化消息origin校验。
- UI-D：紧凑真实进度与端到端回归。复用 `FixedWorkflowStatus` 与已有工件；与编排负责人只对齐所需消费字段，不并行改Host launcher/知识绑定/业务发布。

共享UI及Pair client为本UI负责人范围；引擎、Host、DSH调度、真实模型和运行环境归主Agent/编排负责人。首轮先写本规格，成块实现经现有 OpenCode 服务、显式 `opencode-go/deepseek-v4.1-flash`，由Codex复核实际diff和真实界面，不将CLI成功当成验收。

## 7. 验收清单

- 在独立候选而非演示现场核对1104×780、1024×675，以及宿主宽度变化：无页面横向溢出，正文/PDF可读，树可访问，导航和配置不挤占主要阅读区。
- 同一含正文/附件/父正文/子条目/表格/跨页内容的fixture，走结构→原文→需求→分析。原编号、完整原文、来源顺序、SRC/REQ、父项/派生关系保持；原文与PDF框一致。
- 原文视图无过早的分析结论列；需求视图只展示真实已识别需求但不丢祖先；分析视图显示当前建议/依据并区分人工响应。
- 空/部分保存、非需求、缺依据、读取失败、旧版本、迟到请求、快速切换、切换语言和窄屏均不产生假完成、假零值或跨项串框。
- 键盘能切换阶段、展开树、选择条目、定位原页和收回抽屉；焦点可见，状态不只靠颜色表达。
- 聚焦测试、TypeScript/生产构建、机械设计检测及真实渲染分别记录；只有业务真实任务才能证明保存/分析/导出完整链路。源码审计不能替代上述验证。
