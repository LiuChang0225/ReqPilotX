# 原条号集合与派生投影

更新：2026-09-08。实现位于 `source_item_visual.py` 的来源核验与
`source_item_delivery.py` 的共享交付投影。不改原文条目、派生正文或Snn身份。

## 来源与投影

原条号的权威是已编译标注中的 `source_numbers: [{value, evidence}]`。
每个值有精确原文编号位置；可选 `evidence.source_extent` 明确该原号对应的原文范围。
delivery调用 `validate_source_item_numbers` 再验证这些位置，不从相邻编号推断范围。
旧scalar有精确证据时沿用该证据；只有scalar的既有标注继续使用原有来源检查。

父项多个原号在既有 `MatrixNodeStateV1.source_number` 中明确显示为“原条号 6.1、6.2”，
完整集合保留在 `source_item.source_numbers`。这是一份集合的阅读投影，不生成一个拼接后的客户编号。

派生项继续使用同一个typed字段进入工作台Matrix和Excel独立原编号列：

- 编号位置被派生项的准确直接依据包含，或显式extent完整覆盖其所有直接依据，而且匹配唯一时，显示该原号。
- 只有一个父项原号且没有更窄的显式extent时，可继承该原号，metadata标为`SINGLE_PARENT_NUMBER`。
- 多个原号不能唯一对应时，显示“父项原条号…；本项见原文依据”，标为`PARENT_NUMBER_CONTEXT`。
- 不存在父项原号时保持空白；不能用REQ或Snn填充原编号。

`decomposition.source_number_projection` 保存投影角色及完整编号证据集合，只存在于交付读模型中；
不写回原始派生工件。精确匹配角色为`EXACT_SOURCE_NUMBER`。

## 匹配边界

匹配使用编译后的 `source_excerpts.source_ref`，其中TEXT字符偏移是原content的绝对偏移，
不是子项`source_ranges`中的segment相对偏移。TABLE_CELL的`table_id`与编号证据中的
`fragment_id`对应同一物理片段，还必须匹配cell ID与完整字符区间。

extent必须覆盖全部直接依据；只覆盖一部分不能认定完整归属。重复原号可以来自不同原文位置，
按位置分别保留；若同一子项匹配多个位置，即便值相同，也不能假装已经唯一定位。

原编号展示字段的160字符限制只影响长集合的提示文本；省略时显示总处数，并保留完整证据集合，
引导回原文依据，不截断后冒充一个精确编号。

## 验证

`prototype/tests/test_source_item_delivery_numbers.py`的10项专属检查覆盖直接编号、无编号子项的
显式extent、无extent时的父项上下文、重复编号位置、重签错误证据拒绝、绝对偏移、table/fragment
身份对应、长度边界，以及同一typed字段到Excel的实际输出。它们与跨Map派生继承、既有继承保护、
交付说明和Matrix检查一起运行，本轮54项通过。

真实E01后继的编号采集/验收由该次运行的来源证据和导出回执另行证明，不能只凭这组合成回归宣称
原文编号已经全部补齐。
