# PRD: SOR/PDS 章节拆解引擎（预防式架构）v1

更新时间：2026-03-02  
负责人：Extractor/Parser/Fidelity 联合改造  
状态：Ready for Implementation

---

## 1. 背景

当前系统已在多份文字类 SOR/PDS 文档上达到高可用拆解效果，但仍暴露出一个关键风险：  
当文档出现“跨页表格 + 枚举条款 + 混排正文”时，若先做删除去噪再补救，可能引入条款丢失或顺序回退（如 `3.2.2` 的 `9）~15）`）。

业务底线明确：
- 第一优先级始终是“条目拆解准确”（完整、顺序、归属正确）。
- 不能接受“看似整洁但丢条款”。

因此本 PRD 将当前策略升级为：**从异常后补救，转为预防式拆解**。

---

## 2. 目标与非目标

## 2.1 目标（Must）
- 章节/子章节完整提取，避免漏项。
- 条目顺序稳定，不因去噪或重排导致回退。
- 表格跨页连续，避免断裂或串章。
- 附件（A/B/C... 或 T/U/V...）独立命名空间，避免与正文互相污染。
- 上线硬门禁：缺失、乱序、串章任一命中即回归失败。

## 2.2 非目标（This Round）
- 不处理扫描件 OCR 强化（如纯图片 PDF）；仍聚焦文字类 PDF。
- 不在本轮投入 type accuracy（Accept/Reject 分类由后续 LLM/RAG 迭代）。

## 2.3 当前技术边界（必须明确）
- 当前能力是“结构恢复 + 内容恢复”，不是“原 PDF 像素级版式复刻”。
- 表格恢复本质是：文本行 -> markdown 表格 -> 前端 HTML 表格，不等同于原始单元格几何重建。
- 因此在复杂跨页合并单元格场景中，可能出现字段错位或桥接残留（如 `0.0 左后主动减振器总成`、`21.92万台车/5` 误入）。
- 本 PRD 的新增目标是把该边界从“近似恢复”推进到“字段级恢复优先”，并用门禁防回退。

---

## 3. 现存问题抽象

现问题不是单一文档问题，而是同类模式共性：
- 混排 mega-line（长行聚合）与真实分行并存，导致“删错即丢条款”。
- 纯编号拓扑在弱格式文档中不够，需要与版面结构联合判断。
- 跨页表格续接时，若桥接行判错，会把后续编号段误并入前表。
- 附件章节与正文章节同号，若无作用域隔离会错误覆盖。

## 4. 产品方案（预防式）

## 4.1 总体原则
- **完整优先**：宁可保留轻微冗余，不可丢失条款。
- **结构先行**：先建立文档块图，再做章节与条目归并。
- **最小破坏**：默认不做 destructive delete；删除必须满足可回放与可证据化。

## 4.2 核心流程（新）
1. 解析层输出 `BlockGraph`：文本块/表格块/标题候选块（含页号、bbox、来源引擎、置信度）。  
2. 章节检测层构建 `SectionTree`：支持正文与附件多作用域。  
3. 归属层按“页序 + 几何邻近 + 编号拓扑 + 关键词锚点”计算所属章节。  
4. 条目层执行“按章节完整块”归并；对试验大纲表格按序号聚合条目。  
5. 保序层做最小重排（只在同章节内，且必须有证据）。  
6. 门禁层执行结构与内容双回归，失败即阻断。

## 5. 关键设计细则

## 5.1 去噪策略（替代“先删后补”）
- 去噪对象分级：`watermark/header/footer/noise-fragment`。
- 删除前置条件：
  - 与正文 token 重叠率低；
  - 在多页重复出现；
  - 位置信息符合边界区域或固定斜向 pattern；
  - 删除后不会造成枚举链断裂（由 coverage check 保护）。
- 删除动作改为“标记 + 折叠”，而非直接丢弃原始证据。

## 5.2 枚举条款保护（通用，不写死单章节）
- 枚举识别统一语法：
  - 一级：`n） n) n、`
  - 多级：`n.m） n.m.n）`
  - 子项：`（1） (1)`，勾选项：`[ ] [√] [x]`
- 保护规则：
  - 若检测到同一段内存在连续枚举链（如 `9~15`），则链内条款设为“不可删除单元”。
  - 若发生归并/去噪，必须先做链完整性比对（count + ordered codes）。
  - 任何链断裂自动触发回退到上一步候选版本。

## 5.3 编号拓扑 + 版面结构联合
- 编号拓扑只作为一个信号，不单独做最终归属。
- 归属评分模型（规则版）：
  - `S = a*page_proximity + b*bbox_flow + c*code_parent + d*title_anchor + e*table_continuity`
- 仅当 `S` 超阈值才迁移条目；否则保持原章节并打 `needs_review` 标记。

## 5.4 跨页表格连续性
- 构建表格实例 ID（header 指纹 + 列结构 + 邻页连续性）。
- 满足以下条件则自动续接：
  - 下一页出现相同或近似表头；
  - 行号单调递增或合并单元格延续；
  - 两页间无新的强主标题切断。
- 对试验大纲场景：
  - 同序号多行步骤合并为一个 requirement；
  - 保留原始子步骤明细在 `sub_rows` 字段中以便 UI 展开。

## 5.5 正文/附件作用域
- 正文作用域：`Main`
- 附件作用域：`Appendix:<token>`（A/B/C... 或 T/U/V...）
- 同号章节仅在作用域内比较拓扑，不跨域重排。
- UI 与回归全部使用 `scoped_code` 作为唯一键。

## 5.6 PDF 格式恢复升级（字段级）
- 升级目标：从“文本化表格”升级为“几何驱动字段恢复”。
- 核心方法：
  - 基于 `PyMuPDF rawdict/pdfplumber` 的 bbox 建立 `CellGraph`（行、列、合并单元格关系）。
  - 用列锚点（如 `序号/层级/代号/版本/名称/重量/数量/开发状态`）做表头模板匹配。
  - 以“列模板 + 行号单调 + 页序连续”约束跨页续表。
  - 当结构置信度不足时，回退到 markdown 模式并标记 `needs_review`，禁止静默错位。
- 关键收益：
  - 降低 `2.1/2.1.1` 串行化风险。
  - 降低 BOM 与试验表格字段错位。
  - 为 UI 原文对照提供可定位的来源坐标。

## 6. 门禁体系（硬门禁）

## 6.1 结构门禁
- 最小章节数、最小条目数、章节一致性问题上限。
- 必需作用域与必需章节码存在性。
- 列表样式误识别、短深层标题异常等计数上限。

## 6.2 内容门禁
- `required_requirement_text_contains`：关键语句存在。
- `forbidden_requirement_text_contains`：串章污染语句禁止出现。
- `required_requirement_ordered_snippets`：同一章节内关键片段必须存在且顺序单调。

## 6.3 发布门禁
- `run_regression.sh` 必须全通过（允许通过参数排除扫描件）。
- 任一 high severity issue 直接阻断合入。

## 7. 数据与接口改造

## 7.1 数据结构新增
- `block_id / page / bbox / source_engine / confidence / scope`
- `requirement_id` 绑定 `source_block_ids`
- `integrity_flags`：
  - `enum_chain_protected`
  - `cross_page_table_joined`
  - `needs_review`

## 7.2 API 增强
- extraction preview 返回：
  - `section_overview`（统一替代“章节树 + 覆盖”双视图）
  - `trace`（每条 requirement 的来源块与排序依据）
  - `integrity_checks`（链完整性、续表完整性）

## 7.3 新增字段（用于原文对照与右侧 PDF 联动）
- requirement 级：
  - `source_page_start / source_page_end`
  - `source_bbox_union`（可选，整条目高亮框）
  - `source_block_ids`（追踪来源块）
- 表格级（可选）：
  - `table_id`
  - `table_schema`（列名与列序）
  - `row_spans` / `col_spans`
  - `cell_bboxes`
- 前端联动接口：
  - `GET /api/extraction-preview/page/{page_no}`（按页获取可高亮块）
  - `GET /api/extraction-preview/requirement/{req_code}/trace`（定位来源）

## 8. UI 需求（开发者侧）

- 在审阅台展示统一的“章节总揽”：
  - `scoped_code`、标题、页码范围、条目数、风险标记。
- 在完整需求条目中支持：
  - Markdown 表格恢复为可视化表格；
  - 同序号多行步骤折叠/展开；
  - 一键定位来源页与来源块。

## 8.1 完整需求条目表格改版（已确认需求）
- 删除列：`类型`、`优先级`、`长度`。
- 扩展 `需求文本` 列宽为主视区，至少占内容区 60%。
- 默认展示核心列：
  - `REQ`
  - `章节`
  - `页码`
  - `需求文本`
  - `需求候选`
  - `操作`
- 保留高级信息入口（折叠详情或 hover），避免信息丢失但不占主空间。

## 8.2 右侧原 PDF 浏览页（对照模式）
- 布局：左右分栏
  - 左：条目列表/表格
  - 右：PDF Viewer（内嵌）
- 交互：
  - 点击左侧条目 -> 右侧跳转到 `source_page_start` 并高亮 `source_bbox_union`。
  - 在右侧翻页 -> 左侧自动定位当前页关联条目（可选开关）。
  - 支持单页/连续滚动两种阅读模式。
- 技术选型：
  - 前端使用 `pdf.js`（稳定、可控、支持文本层和高亮层）。
  - 高亮层采用绝对定位 overlay，坐标使用解析层返回 bbox。
- 兼容策略：
  - 若无 bbox，仅做页级跳转与条目定位，不阻断功能。

## 10. 验收标准

## 10.1 功能验收
- `3.2.2` 类复杂章节在多轮迭代中不再出现 `9~15` 缺失或乱序。
- 试验大纲表格按序号聚合稳定，不再按步骤分裂成多个独立 requirement。
- 附件章节与正文无串章。
- 完整需求条目表格不再显示 `类型/优先级/长度`，文本列明显扩展。
- 左侧条目与右侧 PDF 能实现稳定页级联动。
- 对含 bbox 的条目，右侧可高亮原文范围；无 bbox 时至少页级跳转准确。

## 10.2 质量验收
- 文字类回归集通过率达到并维持 `>=95%`。
- 关键样本（Q-JLY / SOR-BAIC / PDS active damper）门禁全绿。
- 新增规则不得导致既有 profile 大面积漂移（drift 在配置阈值内）。

## 11. 风险与应对

- 风险：规则复杂度上升导致维护成本增加。  
  应对：规则模块化 + profile 化配置 + trace 可解释化。

- 风险：个别文档存在极端排版，评分模型冲突。  
  应对：保守归属（不强迁移）+ `needs_review` 标记兜底。

- 风险：为了“整洁”再次引入破坏性删除。  
  应对：删除保护作为框架级约束，门禁中增加“链完整性失败即阻断”。
