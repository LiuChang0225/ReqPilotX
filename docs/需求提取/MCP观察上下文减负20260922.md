# MCP 观察上下文减负

2026-09-22。本页说明新仓库接入的会话运输行为。旧实施原稿及真实文档回执留在私有资料中，不把旧验证结果当成本次重新执行的成绩。

## 行为与边界

- `task_open` 或显式读取建立唯一已观察任务后，普通 MCP 读写可省略 `task_id`；观察到多个任务时必须显式选择，不猜最后一个或目录 latest。
- 写入可省略 `expected_revision`，适配器补入实际观察到的版本。外部写入推进状态后，旧观察仍触发原 CAS 冲突；失败不刷新观察，显式字段和 null 仍按业务 schema 校验。
- 同一连接的相同隐式写请求保持原版本和命令号。重新回读后有意再次执行同一决定，应使用新 `command_id` 或显式观察版本。
- 回执提供 `request_context`。重连后可使用原命令号从既有 operation 恢复原始版本；固定 CLI 继续校验完整请求摘要，修改决定但复用命令号仍冲突。
- 并发回复不能根据到达顺序推断最新状态；发生观察失序后需重新读取。重启不扫描目录恢复“当前任务”，没有新增持久化工作流账本。
- MCP 发现 schema 仅放宽运输字段的必填。底层 REQUESTS、typed CLI 和 `task_describe` 业务 schema 保持显式；普通 describe 不自动选择任务，workbench 发布仍明确提供发布版本。

实现：[会话上下文](../../plugins/reqpilot/scripts/task_session.py)、[MCP适配](../../plugins/reqpilot/scripts/mcp_server.py)、[固定CLI桥接](../../plugins/reqpilot/scripts/task_bridge.py)。领域语义、来源范围、分类、编号依据和视觉校正仍由原有业务合同处理。

## 验证与接续

行为检查覆盖单/多任务、显式值、并发观察、失败不刷新、原命令恢复和固定旧包兼容；真实 stdio 测试覆盖外部写入冲突、重启重放及 MCP/CLI 业务成果一致性。精确本机执行结果保存在源码仓库外的接入记录中。

这些程序检查不证明模型耗时改善或客户来源语义通过。未调用模型、未更新全局安装、未替换历史任务包。编号入口及阶段输入见[编号与阶段准备](原编号绑定减负与阶段评测准备20260922.md)，后续仍遵循[开发计划](开发计划.md)。
