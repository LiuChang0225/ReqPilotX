# Pair 任务隔离 MCP 接入

2026-09-22。原生付费试验暴露了原生 TaskLauncher 只有 CLI、而评测已有 MCP 的差异。本轮将已有 ReqPilot stdio 服务接入 DSH 官方 MCP 桥接器；业务工具、schema、技能和任务状态仍只有共同能力包一份维护源。

## 实现

- 共用 `host_launch.py` 返回 `reqpilot-host-tools/v1` 描述：固定包内 MCP 入口、解释器、工作根及来源根。`--describe` 提供无需创建任务的协议检查。
- Pair Bundle 启用 `taskMcp`；Host 显式依赖 `@deepseek-ai/dsh-mcp-client` 的已验证 `0.1.5-rc.2`。Python 依赖沿用 `plugins/reqpilot/requirements-mcp.txt` 的 `mcp==2.2.0`。
- 初始化先检查共同能力包协议、MCP SDK接口和doctor，再开放开始任务。
- 新任务持久回执固定 `toolTransport=MCP`；旧任务继续CLI，不更换已有执行环境。
- `toolBinding` 只为回执中同一Session返回其固定工具描述；校验解释器、入口、工作/来源根、任务状态及运行地址。其它会话没有这份绑定。
- `agent/created` 给该Agent上下文安装 `system-prompt/assemble` 拦截器。首次装配挂载DSH官方MCP插件，等待其连接/工具发现，调用 `next()`，再通过公开装配器重建一次工具列表。后续复用已挂载实例。Agent销毁或Host插件卸载都会幂等处置该Agent的拦截器和桥接器；Host卸载先停止新安装，再等待首次导入、连接、在途装配和官方stdio/工具注销收敛，不销毁Agent本身。
- 首个尝试使用 `agent/pre-step`，实测发现该时点已经收集好工具schema，因此首请求看不到工具。已换为上面的装配接入，不修改DSH的Agent loop，不复制preset，不全局注册某份文档的MCP。

## 边界与下一步

本轮MCP证明了真实注册、调用、双任务隔离和Host卸载回收，不是付费模型完整提取/效率证明。旧付费CLI试验的成绩仍归原包、原环境。长任务重连/压力和MCP版付费文档闭环尚待验证。

`events.agent`仍为false，执行状态采用真实日志的只读快照轮询；取消和业务端点重连尚未完成。旧任务端点变化后仍拒绝继续写入，不能通过重新生成任务或偷偷改绑定来宣称恢复。
