# 统一工作流与工作台专项：UI首个切片实施记录

更新：2026-09-12。依据用户“下一步计划也同时实施”的授权，接续[专项主稿](统一工作流与工作台专项.md)和[UI协作意见](统一工作流与工作台专项-UI协作意见.md)。本记录只覆盖P1/P2首个前端切片，不宣称P3旧入口全部迁移、完整外部人工依据传输或模型质量评测完成。

## 本轮实现

- **同一文档外壳**：取消`DocumentWorkSurface`的plugin early return。插件与native在同一外壳内保留主区、协作入口、查看版本及范围绑定；插件不再自建第二个`document-work-surface`。
- **适配器与控制分开**：`usePluginWorkbench`承担插件读取、版本和命令；`PluginWorkbench`只渲染该查看版的主区内容；`AgentPanelFrame`供native/外部协作共用。native继续用原有`SourceItemAgentLoop`控制器；外部页不挂载native执行控制器，也不为显示协作另开模型。
- **外部状态诚实表达**：`UNREPORTED`显示外部运行未报告；最近同步与执行状态分开。已有目标、阶段成果、意见和修订报告可查。没有取回回执不声称已送达或执行；修订报告显示“待核对”，不冒充工程师接受。复制接续说明明确只是复制，不声称自动唤醒对话。
- **版本/命令绑定**：外部查看版写入`resultRevision`路由；刷新及原文/分析/交付导航不换成最新head。新版本到达保留正在看的版本和草稿。已选producer/版本按项目、文档、原件SHA记忆；文档列表或阅读返回时可恢复，跨来源不复用。反馈与确认重试保留同一`command_id`；不确定网络结果不换UUID。当前后端只允许最新head写入时，历史版明确只读并保留本机草稿。
- **交付目的正确**：plugin `task=export`进入当前核对版交付摘要和历史成果列表，按该revision生成下载链接，保留协作区；不再仍显示提取主体。native读取404不再隐式回退另一套legacy Matrix；显式旧Set路径保留。
- **共同原编号与统计**：条目台账独立显示客户原编号及系统标识。详情/树消费共用编号字段；无编号不拿章号或REQ替代，Snn明确显示来源原编号。章统计使用scope_summaries，提示中区分子树/直属/派生/分析单元，缺摘要时只说直属数量。原编号也可搜索，不由UI正则推号。
- **来源提示**：消费同一`source_findings`，展示限定扫描范围、编号观察、待回查状态及两端定位；`2.6→2.10`不被当作已经确认的原件漏号，不自动补号或生成新需求。Map-only通过reader/reference顶层提供的发现同样可读。未提供finding resolve API，本切片没有“已核实/关闭”假动作。
- **视图用途与密度**：显示方式明确为“条目台账/原页对照”，提示其用途和不重新提取的边界；保留完整父条款、派生独立行、键盘、列宽、原图与完整内容。既有约83px的两行工具栏保持。
- **处置记录兼容**：新decomposition的KEEP/UNDO/SPLIT理由及授权范围剩余数量，可在既有拆分区按需展开；不补造旧版缺失理由，不把1/13已处置称为13项完成。

本任务只改frontend及本任务负责的UI文档，没有改backend/plugin脚本、主计划、主接续或服务启动方式。此前W09“tuple索引误报”已由业务任务复查撤回，本轮不以它为实现依据，也未修改相关索引。
