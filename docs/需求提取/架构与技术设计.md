## 2026-09-09 阶段与读取职责

2026-09-11任务输入增量：稳定业务委托、职责与六步成果路线由显式挂载的主skill提供；`native_task_brief`按本轮请求及宿主工件/确认/依据状态生成动态简报。两个worker与评测共用renderer，运行前保存实际发送内容，`reqpilot_context.task_brief`可刷新状态；这些是事实提示，不新增业务门禁或固定读取算法。主skill以实际冻结能力包为准，旧包不因开发源变化而升级。详见[任务简报](Agent任务简报与阶段交接.md)。

- 应用负责来源/内部依据入口、阶段工件发布、确认点、进度事件、版本竞争、恢复和程序导出。Agent自由选择读取工具、调查范围、回查和语义修订；不把工具序列硬编码为业务真相。
- 共用业务阶段为结构→条目/分类→拆分处置→可选证据分析→人工响应/Matrix；用户明确要求先确认结构时等待该点，不扩大为逐条审批。
- 无知识库或其他授权内部依据时跳过自动符合性分析，执行状态与“已分析但缺证据”区分，旧工件保持。新任务已接入口选择、结构/条目阶段发布和Map版本确认；其他阶段与复杂范围继续核对。
- 发布时校验图谱并形成版本绑定的只读索引；条目详情取最小必要数据和关联，校验当前版本，不再每次点击重复全量编译/深拷贝。首轮已实现进程内紧凑读取缓存，每次保留存储字节及当前发布校验；持久化只读索引未另建。
- UI和Excel共用同版业务投影及主类型；表内图作为内容，不改变表格身份。导出由程序消费已形成结果，格式渲染与业务判定分责。
- 首次基线按统一来源顺序发SRC，REQ为对应子集；修订后稳定号码与阅读顺序分开。具体采用及迁移边界见[编号方案](SRC与REQ编号及显示顺序.md)。

## 1. 四个稳定边界

2026-09-10 Q17开发增量：`compile-map`可接受轻量`reqpilot-map-edit/v1`及可选前版`map_dir`，由共享程序解析已有来源索引/唯一原文标记、生成普通Map v2决定并编译原有工件。局部编辑保留未改字段、前版与来源身份，仍由Agent决定语义归属；应用最终验证按同一输入及前版重放。每次成功编译沿用既有阶段保存/读取路径，尚未实施Q18前端渐进呈现。方法/验证/发布边界见[Q17首轮](Q17机械工作收敛首轮.md)。

后继[读取到首次编制](Q17读取到首次编制.md)：`inspect-source`新增可选authoring只读视图，按请求页/子串/索引返回完整来源内容、可引用索引、真实表格字段和进一步读取参数，保留原始证据入口及并行捕获，不新增语义判定。原生上下文明确来源路径/命令证据目录，skill按当前阶段加载；它是编制便利层，不是第二套业务结构或算法观察白名单。

同轮因真实模型误把编号义务改为标题，Map编辑新增`numbered_body`便利字段：只将明确选中的原编号绑定为标题/标签证据，剩余完整文字进入原有非标题source_content；不推断是否应拆分、不替Agent选择业务范围。原始v2决定与持久化模型保持不变，编译失败提示不再迫使模型将义务标题化。

后继[评测环境与结果自查](评测环境与结果自查.md)：编译追加只读`map-review.json`，小结果直接返回正文/标题角色、父子引用、表图和同位置并行捕获线索；不改变Map语义或自动消除重复。已存草稿允许继续同范围自查，人工确认仍约束进入条目阶段。生产和SDK评测共用`source_document_goal`，评测显式区分原件起步/材料齐备、观察时点/硬超时、开发回归/保留集；SDK/工具宿主验证不冒充队列、数据库和UI全链路。原生capture的原件SHA可由宿主补齐，并兼容CLI的显式expected_sha256参数。

2026-09-10 [跨文档迁移与续接](跨文档迁移与运行时续接验证.md)：评测交付使用宿主校验后的文件引用，不重写模型原答。二进制更新后的旧会话可通过显式runtime revalidation读取同一SDK线程、验证当前协议与原生约束后仅更新binary pin；来源绑定、模型、认证home、工具/技能和历史执行回执保持原样。普通run仍拒绝未授权身份漂移；该维护不替代技能能力epoch，也不启动客户模型或作业务接受。

2026-09-11 [实际应用复验](真实PDF应用链路复验.md)：Map阶段已经通过真实上传/队列/worker进入工作台，可在模型运行中显示并保持正在核对的版本；该应用证据不保证Map语义正确。共享编译器新增对象路径级的必填字段预检，不更改有效工件内容。`native_loop_progress.native_tool_activity`将实际工具操作映射为固定公开文案，供两种原生任务心跳及事件投影共用；不公开原始参数，不用模型额外生成状态，也不把调用开始标为完成。

同轮反馈续接复用了原SDK线程与任务能力包，只有受影响Map局部修订进入新阶段。后继宿主与CLI将`max_results`规范化为同义`limit`；不支持的上下文参数一次报告，不能静默省略其读取意图。无效JSON pointer返回实际根读取参数，`/`仍保留空名称键语义。参数容错不扩大来源权限或改变提取边界。

后继[证据引用与PDF补读接口](证据引用与PDF补读接口.md)：节点可选`evidence_anchors`只保留核对定位，不进入内容/表格范围与覆盖计数；空值不改变旧工件。`capture-pdf-text`通过原PDF绘制记录追加带方法、片段和可见性说明的SourceIR节点，旧节点与索引保留，文件哈希区分具体捕获版本。Map编译验证原件重放及只追加关系，应用发布回溯真实capture→补读生产链；原件、旧捕获与人工决定不覆盖。完整父表/子条目继续走原业务关系，不按重叠自动删除。

1. **原文证据**：原始字节、来源身份、页面/文本/表格/资产及定位关系。
2. **用户入口与内部对象**：用户只选择客户需求文档或内部知识；格式不决定入口。验证规范、下游工件、附件等仅是入口内的处理对象。
3. **业务成果**：在正确产品对象内形成结构归属、原文条目、分类、派生单一需求、用户反馈和版本。
4. **宿主执行**：会话、工具权限、模型、并发、活动、暂停/恢复和 UI 接线。

业务规则只存在一份。Codex App、可移植插件和 ReqPilotX App 消费同一规则与可验证工件，
宿主差异不生成第二套语义权威。

## 分析上下文与展示

Agent对每条的理解必须先定位所属文档与完整章节路径，并读取相关上级正文、作用对象、相邻条款、引用与例外。Matrix节点详情的path继续保留完整祖先及其正文；候选原文的applicabilityScope只决定UI默认共同显示的明确适用条款，不是分析上下文白名单。通用概述可以不重复展开，但不能从分析可访问来源中删除。已有合成内部依据分析验证不能当作真实客户知识库；无内部依据的任务应采用上述跳过分支。

## 2. 原文与业务对象

对象与关系以[文档结构与原文条目模型V1](文档结构与原文条目模型V1.md)为当前定义：组织位置、内容形式、内容判定、来源与关联分开；原文包含、派生、引用/上下文分别保存。组织树递归且允许直接内容，不设置必须经过的固定层级；条款/整表与SourceItem为1:1时共用可见行，混合内容可以属于同一条目。普通无编号段落已用PARAGRAPH表达；混合内容直接绑定和主类型共同投影仍按案例完善，不能据枚举存在声称语义正确。原编号默认叶级及整体例外以模型V1的9/9补充为准。

- SourceIR / TableIR 保存来源事实，不被模型或浏览器覆写。
- 原文结构表达直接内容归属与逻辑表/附件关系，不从页号或 parser 顺序机械推出语义。
- SourceItem 表达可独立检查的原文条目，可以是需求或有意义的非需求。
- 需求属性拆为是否需求、需求类型、内容角色等维度，兼容字段不替代专业判断。
- SingularRequirement 是用户显式要求后的派生项，绑定原文父项和精确来源，标明逐字片段或规范化派生。
- 结构父子是文档组织；需求派生/分配关系另存，不混为同一种层级。
- 身份、页/单元格/资产定位、范围与版本由工具验证，不能让模型抄写或创造无业务意义的哈希。
- 页面资源使用工件显式`pages[].renderPath`，显示页签使用`printedLabel`；UI不得从总页数、固定前置页或补零宽度推断。
- 扩展名只选择捕获适配器，不决定业务角色。PDF、DOCX、XLSX均可属于客户需求或内部知识；内部知识不得反向生成客户需求。
- 双语、印刷正文、手写修改和签批层可以映射到同一逻辑对象，但保留独立来源面；未确认的来源面不覆盖另一面。
- 验证规定通过关系连接需求、设备、条件、方法与判据，分类按[规则V1](分类与验证关联规则V1.md)；不另立并列试验需求主类，也不为每个片段新增独立产品类别。私有r3展示投影不冻结正式API。
- 稳定业务身份绑定来源、业务边界、locator与内容/拓扑；adapter内部节点ID和表示版本进入lineage，不单独定义业务变化。

第一阶段可以使用轻量工件；只有真实工作证明需要时才冻结新 schema，不为形式扩建平台。

当前F06实验使用 `prototype/target_review/`：固定原文证据 → 主Agent显式语义决定 → 实验工件 →
原生HTML/JS核对页。Python标准库服务只读固定资源并追加版本绑定反馈；不调用模型、不迁移数据库、
不改变现有App Server与正式React入口。工件格式和案例脚本尚不是分发协议，细节见[运行说明](../../prototype/target_review/README.md)。

全类型实验使用 `prototype/type_review/` 保存私有campaign工件、17类处置、真实预览和版本绑定反馈。
它不执行提取或模型调用，且已因产品负责人纠正范围而降级为证据盘点；不能定义用户入口、当前案例顺序或阶段三路由。

## 当前候选复用主应用UI

## 3. Agent 探索循环

目标 → 全文概览 → 局部精读 → 需要时回看图像/表格/邻接范围 → 提交来源绑定成果 →
校验/展示 → 用户反馈或新证据 → 局部修订。

- Agent 能访问完整授权文档；默认工作集压缩不是读取权限边界。
- 语义范围可共享物理页，但直接来源事实不能无说明重复归属。
- 一份文档的全局发现、已接受范围、未决关系和当前假设必须能接续。
  可使用持续会话，也可用显式工作状态恢复；不要求无限延长一条聊天。
- 需要并行时先明确业务范围、共享上下文与协调责任，不按固定页/行/token 制造条目。
- 模型输出不决定正式发布；来源、范围、结构和数据校验在工具层执行。
- 失败只影响真实范围；已接受结果和未受影响条目不丢失。

原文件尚无 Map 时，顶栏处理入口、主面板空态和 Agent 协作共享按项目、文档和原文件
SHA 绑定的真实任务状态。当前 extraction-loop 优先于旧 document-map 诊断任务；运行、
排队、暂停中或状态尚未同步时，其他提取入口不能重复提交。协作中实际发现或提交成功的
任务会回传同一状态，文档切换后的旧请求不能更新新文档。空态提供“查看 Agent 协作”并
通过 React 展开现有任务面板；任务结束后显示实际终态。已有 Map 的原文树和补全路径
继续使用既有逻辑，不把旧解析驾驶舱的阶段失败解释为当前原文件任务失败。

## 4. 表格和视觉

Agent 识别逻辑表、续表、业务行组、共同适用内容与图像归属。
Host 验证来源关系并复用已有 materializer，不能把物理表/行的候选集合当作语义全集。

选择总表显示完整表格；选择条目显示最近适用表头、当前行组、合并共享值、表注和单元格图像。
紧凑展示不得引入旧 anchor 行内容或错误业务分区表头。
native text 是文字证据，像素是可见性与布局证据，两者冲突保留问题，不伪造恢复。

确定性验证能检查的部分不重复交给模型；复杂展示差异可触发有界的原页/渲染对照复核。
不要求每一条都多跑一个视觉 Agent。

## 5. 工件、记录与反馈

最小可接续状态包含：来源身份、目标/范围、已接受成果、当前 revision、观察到的问题、
工具/动作回执、工件引用、用户反馈、受影响对象及下一步。

- 记录实际执行，不用计时器或回放制造“实时分析”。
- 公开 Activity 不含密钥、机器敏感路径、客户正文或隐藏思维链。
- 客户全文、页图和完整候选只进私有授权目录；仓库和插件只保存可分发的合同与经验。
- 用户反馈绑定来源、对象和版本；执行修订时验证当前版本，不能把旧反馈误作用于新来源。
- Agent代理复核作为候选层保存基准版本、处置、理由、范围、澄清状态与最终负责人状态；
  它不能写入人工反馈事件，也不能覆盖首版或客户原文。
- 前端有效值按“人工修订 > 当前分析候选”投影，同时显式显示候选来源；QA沙盒计数不得标成人工确认。
- requirement scope、semantic facets、page status、evidence precision和visual refs属于可选能力字段；
  统一前端按声明渐进展示，不能让案例专用分支成为第二套schema。
- 显式拆分/合并需要 lineage；相同证据可保留身份，真正拆合产生新关系并保留旧版本。
- 新文件位置、临时 workspace 路径和执行 session ID 不是来源身份。

## 7. 能力包与应用接入

阶段二将公共业务核心与宿主适配分开：核心使用来源/工件接口和领域目标，
适配层映射 Skills 发现、工具、模型/视觉能力、权限、Agent 分工、事件与 UI。
必要能力缺失时明确拒绝相关完整性承诺，不把文字占位当成视觉读取。

阶段三由 ReqPilotX 复用同一核心，负责项目、正式持久化、任务、用户反馈、版本和交付。
原生参考与应用运行按相同案例做业务等价验证，不要求中间工具轨迹逐项相同。

## 8. 保留的工程约束

来源真实性、客户授权、稳定身份、覆盖、有效版本、人工主权和不可逆写入检查始终保留。
Parser、schema、模型、框架或工具的“可用”不等于业务正确，也不决定产品完成。
基线整理不改数据库内容、不重新迁移旧 SQLite、不切换生产模型或自动提交客户文件。

### 表格与图像的候选映射

Agent决定哪些逻辑记录作为原文条目；reviewTables保存原始段、记录绑定与跨行图关联，不能由投影器机械按行决定需求粒度。既有StructuredTable复用同一数据实现完整表/当前行/继承表头/原图；字图来源都回到同一PDF。原图通过校验来源指纹及页内区域的本地裁剪接口读取，生成物不是新的客户来源。Excel图像作为来源辅助表，不增加主清单业务行。
