## 2. 第一性原理：把五个问题分开

目标是保存客户原文实际表达的事项及其关系，使工程人员能够审阅、响应和追溯。一个来源事项可有多个载体；一个载体也可包含多个事项。页面、段落、表格行、OCR 块、读取批次不等于业务边界。

1. **取得证据**：原件哪个范围可读、缺什么、当前观察来自哪个版本？原生文字、表格、高清图和 OCR 是证据路线。
2. **判断语义**：哪些是结构；正文之间是并列事项、同项组成还是适用上下文？有效原编号默认逐级拆分，同项组成保留整体及内部编号。
3. **表达决定**：当前工具能否准确绑定决定涉及的全部范围、归属和关系？不能表达时属于合同缺口，不能迫使 Agent 降类、删范围或伪造标题。
4. **保存与恢复**：决定是否已成为同版本的 Map、Items、关系或修订？公开的任务状态应能定位已保存与剩余内容，不要求 Agent 重建目录和哈希账本。
5. **核对与交付**：原文是否支持边界和分类，工件是否保留全部条件/例外，UI/Excel 是否消费同一有效版本？程序覆盖、语义正确、浏览器可见、工程师接受分别成立。

经Pro评审后，把上述边界方法明确为两个相互配合的问题：**归属：这段原文在哪里完整保存，是哪个主项的组成，还是另成来源条目？关系：其他条目需要引用它，才能理解哪些条件、例外、定义或目标？** “并列/组成/上下文”只是帮助阅读的提示，不是互斥三选一，更不是新增三种业务实体。共同校准义务既可以是独立原文条目，又支配多个试验，不能因为它是上下文而不保存其义务。结构祖先、工程派生、验证目标、依据引用和版本谱系仍分别表达；没有来源依据时不能只凭名词相同连边。

上述步骤是可回查的责任分层，不是不可回退的算法；角色、边界和适用性必要时联合修正。原文明确的独立编号、各自交付/配置/试验、共同主项起止与内部组成是判据线索，而不是仅把“完整业务单元”换一个名称。

本地另核对模型V1 §3：完整试验可共同组成一个条目，也可通过明确关联共同参与评审。整体完整性不等于所有相关内容必须直接拥有在唯一SRC里；不得为统一计数吞掉独立目标要求。此次Luna错误是方法与判据孤立且缺必要关联，不据此禁止所有关联式表达。特定混合BOM组成义务的重复REQ问题仍须修复，不能用此限定绕过。

“可单独检查”不足以判拆分：零件和试验步骤都可单独检查，但可能仍是同一事项组成。“属于同一主题”也不足以判合并：里程碑属于同一项目，却规定不同交付事件。判断应说明原文具体定义的装配配置、试验事件或独立事项，不能用“整份计划/同一章节”代替。

## 3. 根因与针对性处理

| 编号 | 根因及具体表现 | 处理与完成依据 |
|---|---|---|
| C1 决策语言缺少优先次序 | “完整业务单元”边界弹性过大；T05 把日程与产品信息并列描述为保留整体组织；分类、结构保留和 SRC 粒度混用 | 先来源角色，再边界关系，再完整上下文，再分类，最后必要派生；用里程碑/BOM、单试验/多试验的成对源例验证，撤销诱导性的笼统表述 |
| C2 reference 偏重原则，缺少操作闭环 | 普通分类有短例，完整参考 BOM 有可运行示范；规范性 BOM、跨页试验等主要是文字说明；工具示例又分散在 CLI、typed 和原生说明中 | 每个高风险方法提供源例、可接受结果、最小公开操作、保存工件、读回结果及反例；只教当前入口可做的事，工具语法由真实 schema 约束 |
| C3 业务定义与编制合同不一致 | `SourceRequirementRecordV1.validate_record`限制三选一，另一校验还禁止text_bindings与logical_table_scope_id并存；`_record_scope_id`选择一个记录级scope，覆盖原子沿用它。共享正文不能覆盖独立text范围 | 先实现[混合组成归属切片](混合正文表格原文单元表达缺口20260922.md)；区分直接组成与共享引用，贯通原scope覆盖/编号/关联范围原子修订/展示/导出。不是简单删除校验；保留原件/格式/版本限制，字段和兼容方案在实现中确定 |
| C4 机械协议仍占据模型注意力 | schema 猜名、读取上限错误、把字面 query 当语义检索、重复复制状态；不同宿主工具暴露与图像返回方式不同 | 优先使用已返回的 read/next_action、短引用和已观察版本；对确定性字段做程序绑定。用真实入口探针证明可达，记录实际暴露 schema/图片。保留源歧义和过期版本拒绝 |
| C5 保存状态不等于事项解决 | 自查发现可能因附带修订自动变 ADDRESSED；口头 SKIPPED 未持久保存；交付外层 ready 与内层旧 next/LOCAL_ONLY 并存 | 将“已记录/已改动/已复核解决/仍未决”与“分析未做/已登记跳过”分清；顶层返回当前真实完成状态和必要下一步，同版已登记导出可复用 |
| C6 验证对象常被替换 | 文件存在、覆盖通过、同版 Excel、模型自然结束可成立，来源语义仍失败；操作者成功重放未等于新 Agent 自主成功 | 分别记录程序可表达、方法实际执行、语义结果、恢复和交付；先短样本定位再整链，不以固定 SRC/REQ 数或多调用率判质量 |
| C7 经验没有逐项闭合 | 历史文档已规定六项方法要素和分层评测，但没有逐类型的“已有入口/可运行样例/模型使用/实际结果”对账；源技能与任务固定包状态容易混淆 | 为本次方法清单登记来源、当前入口、验证层次和待办，并链接证据；维护者更新一次，不要求运行 Agent 每次填额外经验表。按需加载、保持单一计划和技能维护源 |

以上 C1 的具体诱导程度、C4 各项的时间占比仍待受控验证。C3 有代码与冻结接口审计支持；C5 的自动关闭是否符合所有业务分支需聚焦回归，不能将一个观察外推为全部反馈都丢失。

## 5. 各类型的工具方法清单

这是维护者用于补示范和验收的矩阵，不是运行时必须全读的巨型提示。第一轴是来源可读性（原生/扫描/矢量/混合），第二轴是内容关系（条款/表格/图/上下文等）；同一 BOM 可采用不同读取路线，但业务边界不应被 OCR 介质改变。

下列工具名来自当前 [task API](../../agent-assets/current/plugin-skills/reqpilot/references/task-api.md)。真实可用性以该任务固定包与宿主暴露为准；CLI和旧原生入口只使用已声明的等价操作，不猜同名能力。

| 内容/触发证据 | 读取与判断 | 编制/保存路线 | 必须读回及反例 |
|---|---|---|---|
| 普通编号条款、同块多编号 | `source_read`完整范围及支配标题；有疑点看原页。先分纯标题、编号正文与引用编号 | `map_apply` 的 heading/numbered_body/精确范围；`items_apply`保留结构并提交实际正文；程序绑定原文与身份 | 真实祖先、顺序、父级自身正文、有效编号；引用号/尺寸不是新条款，同块并列正文不能被吞 |
| 封面/目录/文控与混排正文 | 原页确定导航范围，目录只作发现线索；检查独立保密/交付义务 | Map声明真实结构角色，`retain_map_structure`保存整块；混排实质正文单独绑定 | 原材料可读、纯结构不发SRC；不得整页排除义务或把定义假作标题 |
| 独立参数、里程碑 | 读完整表头、行、条件、单位/期限；判断各行是否规定不同事项 | `items_apply`引用真实片段局部行范围，完整条件随记录；共享适用内容另连 | 逐项边界与编号、不漏共同条件；多个工况共同定义一个目标时允许完整参数集 |
| BOM、正文＋表格组成义务 | 原页＋完整表＋引导/尾随正文；判一个总成还是多个完整配置 | 纯表完整记录已有；混合直接归属走待修切片，当前不能用 shared 引用冒充拥有，也不能强造第二REQ | 正文、零件层级、数量/版本/备注、内部编号一起保留；变体之间不乱合 |
| DVP/完整试验、跨页方法与判据 | 完整读取试验起止、前后页、样件/方法/条件/判据和关联目标 | 用同一试验的多行/片段组成记录；必要源条件用 annotations关联。跨载体组成受混合合同约束 | 同试验方法/判据不可遗失；不同试验分别成项；独立报告/校准义务另外识别 |
| 合并表头、共享格、脚注、续表 | `source_read`返回的 table cells/fragment请求＋原页；核对合并跨度、脚注标记、列义和断点 | Map logical_tables绑定实际片段；Items row_groups及已有共享格/上下文关系 | 条件只用于其真实范围；空格不自动缺值，换列义/新标题不能仅因相邻而续接 |
| 整页外框、嵌套表、同单元格多事项 | 原图＋原生文字/表拓扑区分布局容器、实际章节与子表 | 用Map精确文字范围和真实子表归属；同一物理行内横向分割等未支持情况保留具体缺口 | 不把外框强制成一个REQ或伪章节；不能以读取切块重塑业务结构 |
| 协议、枚举、选项、适用矩阵 | 连同定义句、轴/表头、位偏移和勾选状态读取 | 保留完整定义单元及结构化值；独立服务/行为有来源边界时分别成项 | 位偏移不是条款编号；未选项保持可见且按来源判适用，不能把每个交点自动变新需求 |
| 扫描/矢量/混合、关键数值 | 先复用可用原生证据；`source_prepare(mode:ocr)`对受影响页生成Tesseract候选；numbers为替代值、tables需真实区域；`source_read(view:image)`核对 | `source_transcription_revise`只回写有像素依据的文字/单元格；以新refs局部Map/Items编制或修订 | 原图/原OCR/修正分开，比较阈值/符号/单位；新阅读版本不自动修旧条目，无线表拓扑不能据有线表成功外推 |
| 表内图、支持图、独立规范图 | 读原始图片、图注、箭头/图例与周围归属；实际返回图像而非仅路径 | 支持图保留Map/table归属并用`annotations_apply.visual_readings`释读；真正独立图用`image_items_apply` | 表仍是表，图像不多发SRC；可见事实/转录/解释/工程推论分开；纯图派生能力边界不可用虚构文本span绕过 |
| 跨章定义、条件、例外、验证目标 | `context_review/context_candidates`只是候选；补读原文证明适用与排除 | `annotations_apply`保存完整预期context_source_ids集合；已有review按工具返回路线修订 | 读回`linked_context`，保留有效旧链接；同词不等于适用，无内部KB不等于无需源上下文 |
| 双语、标准、附件与版本 | 读原件声明的语言、规范/资料性角色、适用引用；缺附件明确记录 | 保留对应来源和关系；翻译为辅助层，原语言不替换；只分析实际提供的依据 | 不靠标准标题导入未读条文；语言冲突不平均/拼接成新原文；版本和来源身份分开 |
| 局部纠错、编号、发现与派生 | 读当前item/scope/numbering/feedback与父packet；查真实原号和相关上下文 | 新scope用items；已有scope用review修订；编号集合用annotations；Snn用decomposition | 原编号/SRC/REQ/Snn分别保持；编号跳号不补号；无关修订不能自动宣布未决解决 |
| 无KB分析、阶段工件与交付 | task_open/inspect复用真实策略、版本和workbench_url；仅缺信息时澄清 | 已知无内部依据时review_prepare记录skip；已有review策略更新待修；task_deliver程序导出并登记 | 读回实际策略/当前附件/版本；用宿主浏览器打开返回链接。浏览器无能力须明示；交付成功不声称语义或人工接受 |

地图/台账“所有权”不等于工程分配；程序不能凭相邻位置自动选组成关系。一个来源范围可供多个条目引用，直接组成归属和共享引用的覆盖语义必须明确。被选择的来源是当前Map实际拥有的观察，不是全捕获中碰巧文字相同的另一个版本。

## 6. 把示例做成可复用方法，而非继续加散文

每张方法卡由维护者提供：**触发证据 → 最小原文/页图 → 语义选择及反例 → 必要公开操作 → 保存结果 → 原文/结果读回核对 → 常见失败与最小恢复 → 已验证宿主/版本与层次**。它不要求暴露模型内部思维，也不要求每次运行额外填写这些字段。

- 主skill：职责、当前阶段、完成标准、短决策顺序、按需入口。优先改歧义和重复，不增加常驻全文。
- reference：普通稳定情况一个完整示范；边界易混情况一对或少量对照。组合同一源例的语义判断、工具动作与保存结果，减少在十份手册中跳转。
- 示例资产：合成源和实际生成结果随可执行公开入口可达。脚本只重放明确决定，不能隐藏一个替Agent作语义决策的算法。任务ID/哈希/局部引用从当前工具取得，不抄示例里的固定值。
- 测试资产：在包外保留答案和未用于示范的用例；工具探针必须调用受测宿主公开入口。技能格式、脚本通过、Agent读过示例、Agent做对分别记录。
- 初批重点：编号/纯标题、里程碑与参数、完整BOM/独立配置、完整试验/不同试验、共享定义/排除范围、支持图/扫描表/独立图。一般标准与Office不阻塞当前PDF修复，但保持未验清单。

示范资产覆盖正常首次编制、一个有价值的局部修正和一个无需修改的正确结果；这不是要求每次运行制造一次修订来展示自查。工具不支持的目标结果可以作为回归需求，但不能给出虚构可运行的JSON。低层CLI教材保留兼容价值，当前MCP任务不应先被要求手工拼内部编译参数。当前`worked_example.py`明确写入预设判断再调用底层编译器；教材可运行不能代替目标Agent通过当前MCP入口完成同等操作的证明。先核对既有示范原件/输入/输出在当前宿主是否可读，不默认新增一个同名工具。

Pro补充的对照纳入后续样例规格：同一BOM旁的独立材质证书交付；相互依赖但分别交付的里程碑与一次资料包内部清单；共同上位试验号下各自实施/形成结果的试验；同一包络曲线的组成信息与新件/耐久后分别编号的目标；自身有义务的父级条件与纯标题；独立产品目标与引用它的试验。它们是合成设计，不是已跑通过的few-shot，也不是改写用户原编号默认规则。

## 8. 如何避免再用长任务掩盖问题

按错误首次出现的位置定位：证据缺失/误读 → 语义决定错误 → 不能表达/绑定错误 → 保存/状态错误 → 投影错误；**首次可见错误不等于根因**。模型提交两个BOM条目可能源于误判，也可能是迁就工具限制，须结合公开操作/错误回包区分。允许同一案例同时有多个原因；原文、Agent公开提交、编制产物、snapshot、UI/Excel分别对照。工具不可表达的案例不用于纯模型能力比较，仍保留为产品交付失败。

L0用合成内容证明合法表达、真实入口和局部恢复，不运行模型。L1不预先告诉正确skill，再观察实际选择和首件；L2可提供角色及预制Map，但不得宣称证明了自主全文阅读。L3使用之前定义的真实案例，私有原件和评分留包外；已用于调优的范围不改称留出。

工具修复期记录组合改动；稳定工具后需要归因时，在每个宿主/模型内部比较旧/新指引或定向移去某方法卡，其他条件固定。两宿主之间不作纯模型排名。只扩展失败或未决关注点的重复，不自动跑所有类型×模型×版本的全排列。

若专门评估完整示范的效果，A/B应先共用已经澄清的规则与兼容工具，只改变该示范；不要把A保留错误T05、B同时修T05并加示范的结果归为few-shot效果。Pro建议的“两次L1＋单配置两例A/B四次L2”仅为预算上界示意，不是本轮已启动或必须全做的运行清单；发现硬缺口即停止受阻分支，按当前任务选最小有效集合。

主要评测：遗漏/重复、边界、原序/原号、支配条件/例外、组成与共享关系、分类、局部修订保留和同版交付。效率记录首个有内容的Map/Items时间、可避免返工、实际工具时间和可用的请求时段；缺少网络/首delta观测就保留未知。token字符/缓存字段不混算。

新增版式变体只改变表示，不改变含义：结果边界保持，坐标按新原件重新绑定。再加入改变含义的对照（一个配置变两个配置、一步骤变独立试验），期望边界随真实语义改变。不要把“所有变体必须一样”变成另一条错误硬规则。
