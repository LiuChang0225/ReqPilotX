# PDF 处理策略与粒度正反例

更新：2026-09-09。依据用户新规则与 ReqPilotX 历史案例整理。本文的示例均为合成示例，不是客户原文摘录；示例值不构成工程指标建议。产品定义见[模型V1](文档结构与原文条目模型V1.md)，问题证据见[问题汇总](2026-09-09问题汇总与迭代计划.md)。这是可实施手册，未声称全部工具分支已经接通。

## 1. 先分辨介质，再理解文档

PDF 不是一种固定可读性。先对页/区域判断原生文字、扫描、矢量轮廓、混合及噪声；再判断文档是 SOR、全表格表单、试验规范、BOM 还是标准。ISO/英文是语义与编排特征，不是应整本 OCR 的理由。

| 输入特征 | 优先读取方式 | 升级或修复条件 | 必须保留 |
|---|---|---|---|
| 原生文字、章节规整、单栏 | 带位置的文字、目录/编号和字体布局共同恢复结构 | 提取顺序不通、标题与正文错位、文字覆盖明显不足时对照页图 | 原编号、标题正文边界、所属路径、来源位置 |
| 全页或局部扫描 | 页图 + OCR 候选，按布局恢复列/表格；关键数值回看原图 | 小数点、≤/≥、单位、上下标、编号低置信或自相矛盾 | 原始图像和 OCR 证据分开；不猜缺失字符 |
| 字体编码异常或矢量轮廓文字 | 对比提取文字与渲染，再对受影响区域 OCR/视觉读取 | 可见有字而提取为空/乱码 | 保持原件身份；衍生图片/OCR 不替换原件 SHA |
| 混合型 PDF | 逐页/区域选择原生文字与视觉方式，去重重叠文本层 | 文本层与扫描层冲突、跨页断裂 | 同一内容不生成双份 SRC；保留冲突说明 |
| 水印、页眉页脚、批注、印章、表格线等噪声 | 区分正文与重复装饰，结合跨页位置及语义判断 | 噪声遮挡正文，或所谓“页眉”实为版本/保密/适用约束 | 不静默删掉有意义内容；删除候选与实际遮挡范围可回查 |
| 多栏、跨页表、续页重复表头 | 先恢复阅读次序/列流和表片段，再构造逻辑表 | 编号/列义/单位/表名不一致时重新判定是否续表 | 原片段与逻辑表的映射、共享表头和表注适用范围 |
| 全文嵌在一个大表格/页面边框 | 将外框视为布局候选；在内部识别真实章节、正文与子表 | 同一容器跨多个原章节，或有独立表名/网格/编号区 | 真实业务层级；不让页面框成为虚构章节或一条巨型 REQ |
| 少量无法读清或缺附件 | 发布其余可用范围，标出具体页/区域/引用和缺口 | 缺口影响某条含义或来源身份无法确认 | 未知不是空白、已覆盖或符合；不阻断无关范围 |

读取自由不意味着忽略算法。原生捕获、表格网格、`continues`、`applies_to`、`placed_in_cell` 等都作为候选证据供 Agent 读取与裁定。跨页相邻不自动同表，合并格不自动全部下传，OCR 命中不自动成为真实原编号。

## 2. 原编号默认递归拆到最低层

**正文原文有序号，默认沿原序号递归识别到最低层。** 先区分封面/目录等导航文控整体，不能把目录中的条款号当正文拆分。 有意义的最低层正文形成各自 SourceItem；纯标题仍是结构节点。有正文的父条款保留自身正文与作用范围，不能为了拆子项删掉父项，也不能把整段后代全文再复制成父项正文。

例外只有语义上共同构成一个完整可独立分析事项的编号集合，例如一份 BOM、一个试验的方法步骤、同一完整规格中的参数集合。例外要记录组合范围、内部编号与顺序、共同目标和保留整体的理由。仅“同表、同页、有共同标题、读起来较短”不足以例外。

编号是否是条款号、零件行号、步骤号、页码或小数值，要先结合原页确认。默认拆分不等于默认判为需求，也不等于按物理行/每个数字拆分。

## 3. 正例与反例

下表“正确”指目标输出语义，不能据此声称现有模型已自动做到。

| 编号 / 合成原文情形 | 正例：正确组织 | 反例：常见错误 |
|---|---|---|
| G15：封面列项目名、编号、版本、签名，目录列4.1/4.2及页码 | 封面和目录各保留完整可读块，字段/目录项不逐一生成SRC；正文4.1/4.2照常识别 | 把封面每行或目录每个章节号生成SRC/REQ；或直接删掉这些原文 |
| G16：目录末尾与正文首条在同页，或封面附独立保密义务 | 导航/文控区整体保留，真实正文范围单独提取判定 | 按整页标封面/目录而漏掉义务；或仅靠“目录”关键词排除正文 |
| G01：4.1 下有 4.1.1“提供诊断接口”、4.1.2“保存故障记录” | 两个原编号叶级条目，归属 4.1；若 4.1 无正文，仅保留结构 | 合并为一个“诊断要求”SRC；或把 4.1.1/4.1.2 改成 Agent 的 S01/S02 |
| G02：5.2 正文“下列要求在低温条件下适用”，其下 a)、b) 是两项独立性能要求 | 保留父级条件，a)、b) 各有原文范围并关联该条件 | 子项丢条件；或每个子项复制整节作为自己的原文 |
| G03：BOM 行 1 壳体、2 密封圈、3 紧固件，共同定义一个总成 | 整份 BOM 一个业务范围；零件号、数量、装配层级作为内部结构完整保留 | 因有 1/2/3，生成三个独立需求并逐件判符合；或保留整体却删掉零件层级 |
| G04：同表左/右两个独立产品 BOM，分别有各自零件清单 | 若各自完整且需独立处理，形成两个 BOM 分支；分支内部不机械逐件拆 | 整页合成一个范围而混淆产品；或把全部零件摊平为同父条款 |
| G05：试验 7 内步骤 1 预处理、2 施加载荷、3 检查，共同判据在合并格 | 保留完整试验范围及内部步骤编号、方法、条件、判据；多页仍一项 | 把步骤或三物理行各判成独立完整试验，导致任何一项都缺方法/判据 |
| G06：表内试验 1 振动、试验 2 盐雾，各有完整方法与判据 | 总表下两个完整试验条目；各自可跨多行/多页 | 用“整个表是一份内容”为由不拆所有编号试验 |
| G07：同一试验同时有独立电气与机械验收结果，用户需要分别响应 | 原文试验保留整体；必要时建立有依据的 Snn 分析子项并共享方法条件 | 为了分别分析把原始试验树改成客户不存在的两个原编号 |
| G08：原生表格某记录内有尺寸图 | 仍为表格/表格条目，图作为该记录内容；图可放大和释读但不新增虚假独立条目 | 只因有 `figure_refs` 就把主表“结构类型”改成图片 |
| G09：整张表只有扫描图片，但语义明确是多列表格 | 业务对象为表格，图像是来源载体；可读格网与不确定格分别表达 | 文件资源是 PNG 就把整个业务对象认定为独立插图 |
| G10：独立“图 3 系统连接关系”，不属于某表格单元 | 按原图独立组织，保留图注；Agent 释读与原文分开，推断标记依据 | 为统一样式强行改成表格；把推断的接口约束当客户原句 |
| G11：3.1、3.3、3.3 三个实际条款，原件缺 3.2 且重复 3.3 | 三个不同来源对象，原编号照录，系统身份不同，顺序按原件 | 自动补 3.2 或改第二个 3.3 为 3.4；按编号去重丢条目 |
| G12：双层表头“试验项目 / 条件”，其下“温度 / 时长 / 判据” | 共同构成表头上下文；具体行依表义判断 | 第二层表头因为有“判据”词就成为一条 Constraint |
| G13：第 8 页表未完，第 9 页相同列义并延续试验号；第 10 页另起诊断表 | 8–9 页合为逻辑表，10 页另表；重复表头不当新要求 | 按页三表割裂；或把所有相邻表都沿 `continues` 无条件合并 |
| G14：编号 6 下的 a)、b) 各表达独立供货和报告义务 | 默认拆为原文 a)、b) 两项，保留上级作用范围 | 仅因同属“供应商责任”就援引 BOM 例外而合并 |

这一区分同样适用于清单和矩阵：**有编号的独立事项默认逐项；共同定义一个对象的组成/参数默认保存完整单元。** 对两种解释都有来源依据的局部范围标明争议，继续其余范围，不靠全局“一行一需求”或“一表一需求”消除不确定性。

## 4. ISO、英文与其他国外标准

优先依据原件采用的版本、目录、术语约定、条款、附录、表/图/注及引用关系；“国外”不是一种固定结构。不同组织和客户自编规范不能机械套 ISO 行文规则。

- ISO 行文中 shall 表要求、should 表建议、may 表许可、can 表可能性/能力；它们是判断证据，不能仅靠关键词决定客户适用性、需求分类或法律效力。见 [ISO supplementary information](https://www.iso.org/foreword-supplementary-information.html)。
- 区分 normative 与 informative 附录，保留原件标识和引用；不能把资料性内容自动当强制义务，也不能忽视正文明确引用的约束。见 [ISO annex guidance](https://helpdesk-docs.iso.org/article/627-add-annexes)。
- 目录项不是正文条款；术语定义、缩略语、注、示例、参考文献先识别内容角色；有意义的非需求可保留。不要把“NOTE 都不是需求”推广到任意供应商 SOR。
- 规范性引用保存版本、对象及适用范围。未拿到被引文件时保留缺口，不声称已经阅读全文；外部标准也不自动成为本产品能力已符合的证据。
- 原文保留原语言。翻译、术语解释和图片释读作为辅助层，尤其核对否定、例外、单位、上下限及 AND/OR，不能改写来源。

具体起草约定随适用文件核验，入口见 [ISO directives and policies](https://www.iso.org/directives-and-policies.html)。当前还没有经过该矩阵全部类型验证的“通用 ISO 自动解析器”完成证据。

## 5. 把经验变成 Agent 真能使用的 reference

首批至少准备一份从原件到结构树、条目、分类、拆分处置、可选证据、前端及 Excel 的完整合成示例；再配上 G01–G16 的局部对照。示例选择以当前问题覆盖为准，不以数量充当效果。

每例包含：来源片段/页图、正确 Document Map、完整条目及内部关系、分类理由、保留整体或拆分理由、典型错误输出、可机器检查的不变量、语义核对点和预期 UI/Excel。明确哪些约定是模型V1，哪些只是该例判断。

复用[案例原则](../需求提取标准案例.md)中的通用约定；历史真实案例与算法结果按[资料边界](../源码与私有资料边界.md)取用，不作为源码自带答案。保留算法关系候选与 Agent 采纳/拒绝理由，不把旧输出计数当目标答案；开发时用过的示例不再冒充独立评测集。
