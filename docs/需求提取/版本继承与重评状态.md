# 版本继承与重评状态

更新：2026-09-08。适用于同源修订后的原文详情、当前 Matrix 与 Excel 草稿。继承判断由共享 decomposition/assessment 工件及其验证回执决定；界面和导出只投影事实，不生成新的分析、派生或人工决定。

- 已继承的分析显示“沿用前版分析建议；本轮未重新分析”，可查看原始输入基线。连续继承沿 `origin_input_receipt` 回到最初分析输入；当前解释和证据仍保留。
- 已继承的派生只依据 `carry_forward.retained_parent_ids` 标注；存在历史继承记录不代表本轮每个父项均未重拆。
- `stale_parent_ids` 显示需要检查拆分，当前失效子项不重新进入分析集合；其编号和分析失效说明通过历史身份登记回到原文父项。详情不再把“旧派生待复核”显示成“从未派生”。
- `stale_unit_ids` 显示需要重新分析。未重新评估的条目使用已有 `STALE_REFERENCE`，没有虚构的待证据模型结果或符合性结论。具体失效原因未知时，只说明输入一致性核验未通过，不猜测是哪条规则或资料造成。
- 当前原文或派生节点携带 `revision_carry` 阅读注释：实际 operation、来源基线、已有 retained/stale IDs 与说明。它不是第二套业务状态。Excel 在既有分析说明单元格呈现同一信息，不改原文、分类、列结构或表格布局。

实现：`source_item_delivery.source_item_carry_notes`、`SourceItemReasoning.tsx`、`response_matrix._carry_text`。纯知识捕获已移到 `app.application.knowledge_evidence_capture`；原 `knowledge_facts` 兼容导出同一捕获函数，项目数据库目录构建仍由原模块负责。
