# Pair任务准备、会话绑定与请求提交

2026-09-22。本轮实现任务发起的程序接线，不代表生产Pair安装、真实模型执行或全文语义已验收。业务准备仍在共用插件中，Pair仅保存宿主命令/会话回执，不建立第二套来源账本或解析流程。

## 实现链路

1. Pair文档页输入任务目标，可显式选择先确认结构；默认不设置人工阶段门禁。
2. Host记录稳定commandId与应用/项目/文档范围，自动携带当前UI所选sourceSha256，从业务服务读取原件并校验SHA。原件有变化时拒绝继续。
3. 固定能力包的`plugins/reqpilot/scripts/host_launch.py`调用现有bootstrap、OpenRequest、TaskService；生成真正的task目录、TASK.md及共用request.md。复制能力包采用临时目录完成后移动，已有工作不被覆盖。
4. 共用工作台连接成功后，Host持久化task/work与能力包完整bundle SHA，再使用实际DSH的Workspace create、Session create和prompt接口。
5. Session ID、prompt requestId及preset在发起前固定；丢回执重试沿用同一组身份。程序返回ACCEPTED仅表示请求已获接收，不是执行完成或语义通过。
6. 页面可打开返回的确切Pair会话；从条目讨论时，以draftRev保护向已有草稿插入准确来源/工作/revision/条目引用，保留用户草稿且不自动发送；成果列表通过已有业务读取逐步更新。当前为成果轮询，不冒充真实Agent步骤事件。

## 共源与权限边界

- `host_launch.py`只编制任务入口及环境事实，业务目标原样来自请求；角色/分类/阅读/拆分规则继续来自固定包的AGENTS与skills。原生App可复用该入口，Pair没有另一份业务prompt。
- Pair的宿主提示只说明本次展示入口是原生ReqPilotX面板；业务URL是工具传输地址，不要求用户搬运。
- 初始Pair运行沿用可配置preset（默认standard）及共用typed CLI，保留通用读取工具；本轮没有新增MCP工具集合或改模型配置。
- 新任务固定bundle、解释器位置、preset和请求身份。不能用升级后的包静默替换待接收任务。缺少包含host_launch.py的冻结能力包时，启动能力不开放。
- 任务控制回执只在插件私有dataRoot保存；公开API不返回本地绝对工作路径或内部执行命令。Host先通过已有鉴权检查，再处理任务入口。
- 退出插件时先停止接收新启动操作并等待已开始的机械准备，再清理自有运行服务；不会在关闭后新提交模型请求。

## 新增合同与入口

- `REQPILOT_PAIR_CAPABILITY_ROOT`：显式的已构建固定能力包目录；不接受开发源码目录替代。
- `REQPILOT_PAIR_AGENT_PRESET`：可选，默认standard。是否存在及可运行由DSH创建会话时验证；不假装生成新preset。
- `POST /reqpilotx/tasks/start`：commandId、projectId、documentId、sourceSha256、goal及可选requireMapConfirmation。成功返回202与宿主绑定回执。
- `GET /reqpilotx/tasks/{commandId}`：读取启动回执，不启动模型。
- `agent.start`仅在服务就绪、固定包doctor通过且会话/工作区服务存在时声明。resume/cancel/Agent事件仍未实现，不开放其能力标记。

## 修复首次同步的失回执问题

旧逻辑首次分配随机workbench session，若POST已在服务端保存、HTTP回执丢失且本地binding尚未写入，重试可能分配另一个session。现在带task身份的新连接由work_id、source SHA、project/document计算稳定session ID；已保存binding和无task的旧入口保持原行为。

程序故障验证覆盖“业务服务已保存但回执丢失”和“Pair已接收但回执丢失”。稳定ID修复落在共用workbench_tools，所有宿主都受益，不在Pair打私有补丁。
