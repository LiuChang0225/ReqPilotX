# ReqPilotX 需求工程开发计划

更新：2026-09-20。本文件是唯一产品实施顺序；[项目状态](../项目.md)说明已有能力，[当前接续](../active-context.md)提供基线与证据入口。历史阶段计划、进程状态和测试数量不再覆盖这里的顺序。

## 交付目标

默认由 Agent 在授权来源与能力范围自主阅读、提取、自查、局部修正并交付完整草稿。阶段成果持续可见，人工可选介入；用户明确要求先确认结构时才等待。原件、已接受版本和人工意见保持，缺失或歧义明确定位，其余范围继续，不补造来源或“完美”结果。

来源组织、原文条目、分类、显式派生、引用及编号按同一业务模型实现；工作台和 Excel 消费同一版本。来源包含不等于工程派生。普通 Excel 由程序生成，不另加模型重读阶段。无内部依据时跳过自动符合性分析，继续来源整理与人工响应。

## 当前同步基线任务

先完成当前源码的可审查同步：保护原工作区、划清源码与私有资料边界、恢复依赖、检查入口可移植性、执行对应程序回归、合成闭环和授权真实来源的有界验证，记录源码/能力包/输入/结果身份，再形成提交并按用户授权同步 GitHub。当前实际结果由本轮交付证据说明，不在计划中预填完成。

源码候选不携带客户原文、真实答案、知识库或运行资料；历史正文在私有工作区和备份保留。以合成输入验证程序合同、以授权原件验证来源语义，两者分别记录。详见[资料边界](../源码与私有资料边界.md)。

## 后续产品实施顺序

| 顺序 | 工作范围 | 可检查成果 |
|---|---|---|
| 1 | 混合 PDF 读取与可靠条目编制 | 同来源/页图/坐标的原生与视觉观察；跨页完整单元、条件与真实祖先；Map/Items 可编制并同版导出 |
| 2 | 任务身份与机械编制减负 | 可信来源/任务/观察版本自动绑定；原因码、局部键和旧 scope 恢复；过期版本继续拒绝 |
| 3 | 统一工作区与 Pair 完整执行适配 | 原生项目/PDF 入口连接任务发起、work-session 绑定、真实进度、恢复及同版交付；同源业务协议不复制到宿主 |
| 4 | 完整响应、人工依据和旧入口整理 | 同版传输分析/意见、工作与历史选择、旧入口退出路径；不丢已有版本、定位与人工决定 |
| 5 | 新文档与完整产品验收 | 冻结输入/包后自主整链，独立语义评核、真实界面、反馈修订、恢复和 Excel；Office 按依赖扩展 |

首批机械字段归一、读取链接、任务工作区、原编号/计数、KEEP 理由、工作选择、共享 UI 和 Pair 托管入口已有实现；后续动作须先对照代码和聚焦证据，不重复宣称“尚未开始”。相应合同见[统一专项](统一工作流与工作台专项.md)、[任务工作区](任务工作区与接续工具.md)、[跨宿主同源约定](跨宿主共源与DSH插件同步约定.md)、[编制减负](编制机械字段减负20260916.md)。

已有的真实模型评测发现过来源遗漏和编制负担；新版本需重新验证，不能沿用旧安装包的成绩。机械测试失败先在短用例复现、修正并回归，再启动必要的完整模型任务，避免重复长任务替代程序诊断。

## 验证与评测

- 冻结来源、能力包、运行配置和评分范围；不给新模型旧答案、私有评分或开发会话历史。
- 程序完整性、自然完成、源语义、交互、人工接受与发布分别记录。模型完成但来源有遗漏仍不能评为语义通过。
- 观察点不是能力截止；需等待自然结束或记录真实中止原因，不用固定短时截断判定最终完成能力。
- 按真实授权选择模型和宿主；历史模型对照是特定批次的配置，不是未来所有开发/架构任务的永久限制。
- 开发用案例不冒充未调参留出。缺少授权原件或独立宿主环境时说明未验，不编造通过。
- 聚焦测试通过后，只有新改动、失败或未解决疑点才扩大回归。发布依赖与崩溃恢复单独验收。

## 后续工程与范围

大型模块职责拆分、构建体积优化、完整发行包和干净机器验证按实际影响推进；ReqIF writer 尚未交付。它们与首次同步基线的程序可复现性分别报告，不能相互替代。仓库产品化 R1 已为现有便携闭包提供可安装 wheel/sdist、同 identity 插件构建和独立安装验证入口；这不改变本表业务实施顺序，也不表示原生服务、Pair、桌面或所有平台已完成发行验收。

不以新建通用数据库、第二套工作台、进度看板或控制塔为开工前置。Office 不阻塞首个 PDF 原文审阅切片。详细通用原则见[模型 V1](文档结构与原文条目模型V1.md)、[分类 V1](分类与验证关联规则V1.md)、[PDF 策略](PDF处理策略与粒度正反例.md)、[编号合同](SRC与REQ编号及显示顺序.md)。
